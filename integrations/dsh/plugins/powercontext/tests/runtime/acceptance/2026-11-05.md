## Installation and authentication

- Installed the archive through Desktop's **Plugins → Add plugin**, enabled it, and restarted Desktop.
- Connected to a separately running local Server with enforced authentication; its OpenAPI version was `1.1.0`.
- Stored the existing credential in the DSH URL-bound credential file, with file mode `0600` and parent mode `0700`.
- Authenticated liveness and readiness returned HTTP 200. The real MCP endpoint advertised 33 tools.
- In-session `/pc doctor` returned `ok: true` after increasing the local request timeout.

The default one-second HTTP deadline timed out during context preparation. A separate populated-Scope prepare
request took 5.61 seconds. The final local profile override used `requestTimeoutMs: 15000` and `timeoutMs: 20000`;
the package defaults remain unchanged. These values are local acceptance settings, not a general latency guarantee.

## Desktop memory behavior

All test data used a dedicated workspace and Scope. The Desktop model was `glm-5.3`.

1. **Native MCP write:** the model called `mcp__powercontext__remember_memory` with the host-resolved Scope,
   `kind: decision`, and the fact `The Frostbridge-1105 release color is violet-cedar-7382.` After one-time
   approval, the actual tool result returned an active entry, its version reference, and Memory revision 3.
2. **Fresh-session search:** created a new conversation, without branching the write conversation. The prompt
   asked for the release color without including its value. The native `search_memory` call returned hybrid
   search hits containing the fact and citations, and the model answered correctly.
3. **Fresh-session automatic recall:** created another new conversation and required an answer only from
   already injected PowerContext context. The model answered with the same value and the saved entry's citation.
   Desktop's context panel showed one turn, one step, injected content, and zero tool executions.

The Desktop V4 encoder rejects the retired `{ kind: 'plugin', plugin: 'powercontext-dsh' }` source wrapper.
Both recall and Scope-routing snapshots now use `kind: 'plugin:powercontext-dsh'`, matching the host's migration
identity for third-party producers. The installed host's real encoder accepted this form; the model conversations
above then completed successfully.

## Coverage limits

This is actual Desktop acceptance, separate from the deterministic SDK suite pinned to `0.1.2-rc.1`.
It does not establish npm publication, mirror synchronization, Windows installation, or compatibility with every
Server/host version. No Server upgrade or database migration was performed. Credentials and local profile settings
are not included in the repository. First-run configuration UI remains outside this change.
