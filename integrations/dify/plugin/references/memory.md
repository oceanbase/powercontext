# Memory and context

Use `pc_prepare_context(query)` when a task depends on prior work. Its Server-produced context is bounded by the administrator's UTF-8 byte budget. Successful empty context is `status=empty,content=null,content_bytes=0`. An error is not evidence that no Memory exists.

Use `pc_search(query,limit,mode)` for up to eight hits; fts/vector/hybrid/auto availability belongs to the Server. Use `pc_memory_list(include_inactive,states,limit,cursor)` for paginated Atomic Memory inventory. Active entries are the default; include `forgotten`, `merged` and `retired` only when the audit needs them. Preserve each record's complete `artifact` and `state_version`, and copy `next_cursor` unchanged for the next page.

Use `pc_memory_get(artifact=...)` to read an exact Atomic ArtifactRef containing `family=atomic-memory`, `artifact_id` and `revision`. The current revision returns the complete `ArtifactRevision`, including `content.kind` and `content.text`, and the actual Server content ETag in `etag`. Historical revisions have no current write ETag. Alternatively, use `pc_memory_get(citation=...)` with a full legacy citation for exact historical reading; preserve its complete `memory_ref`, `entry_id` and `entry_version_id`. Supply exactly one identity, encoded once as JSON text.

Use `pc_memory_state(artifact_id)` to inspect the current `artifact`, `state`, `state_version` and nullable `merged_into_id`. Lifecycle states are `active`, `forgotten`, `merged` and `retired`.

For an authorized explicit save, use `pc_remember(kind,text,...)`. Its response contains `changed` and `records`; keep each returned Atomic `artifact` and `state_version`. For a correction, use `pc_memory_revise(artifact,if_match,kind,text)` with the exact current artifact and its content ETag from `pc_memory_get`. For removal from active search, use `pc_memory_retire(artifact,state_version)` with the exact current artifact and a nonnegative state version from search, list or `pc_memory_state`. This sets recoverable `forgotten` state and preserves history. Legacy citation writes are unsupported. Conflicts require rereading current content/state and checking that the requested change still applies. Supported kinds and limits are in the provider README. No prompt phrase replaces application write controls or Server permissions.

`pc_capture_source(source_id,content,metadata)` stores explicit evidence with a stable caller-selected Source ID. Remove credentials and unrelated sensitive content before capture. Structured metadata remains an object; `origin=dify` is supplied when absent. Capture does not imply Memory extraction or immediate searchability. Keep its exact Source reference for later Handoff or generation. A write timeout has an unknown outcome and must not cause a blind retry.
