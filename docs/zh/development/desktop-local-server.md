# Desktop 本地 Server 设置

完整本地流程位于“设置与诊断 → Local Server”。首次使用也提供已有 Server 连接路径，选择该路径不会修改本地安装。安装和服务规则由独立 Ops 拥有；Desktop 只转换类型化契约，不执行渲染进程提供的任意命令或原始计划。

## 计划与执行

每次安装、修复和服务修改都需要预检、查看计划及明确执行。原生计划有效期为十分钟，并重新校验资源、绑定和状态身份。预览显示实际程序、配置、数据位置、地址、Server 版本、所需字节、登录启动设置及启动和就绪探测影响。新个人安装遵循 RFC 1733：loopback、SQLite/用户数据和无需模型的基础 Memory。保留已有选择和数据。仅在系统适配器支持时提供登录启动选项，不静默替换不受支持的选择。

进度阶段只是观察，不是持久化证据或完成时间估计。界面分别显示安装、配置、注册、进程、存活和就绪状态。应用级控制器在切换页面时保留长操作。普通刷新只重新检查；明确批准的启动、安装或连接交接才可触发就绪探测。

## 恢复

原生引用文件在既有版本 1 记录中增加可选的已批准 `operation`/`options`；结果和尝试仍以 Ops 日志为准。已有记录不会虚构元数据，仍可查询。拒绝新增字段的旧 bridge 无法读取新写入的引用，恢复期间不要降级控制 bridge；保留引用文件并使用匹配或更新的 bridge。

重开后查询所选操作。只查询该选择，避免对大量历史引用自动启动数千个辅助进程。执行期间仍可查询状态和请求取消。取消不代表回滚。终态失败或确认执行进程中断后，可按原操作、选项和预期尝试重新预检并批准恢复。执行状态未知时不自动恢复。响应丢失后重新读取持久引用，不重复 apply。其他绑定、归属冲突、端口占用、资源损坏和数据库不兼容保留生产者的独立错误及可行下一步。

## 连接与移除

明确连接时重新检查原生归属和资源，使用实际地址。固定资源的 `qualification_ref` 必须等于内置且匹配当前 HTTP 契约的 Desktop 兼容配置 ID，资源摘要须匹配检查结果。发行方只能在资格验证后设置该映射。资源的 `source_refs` 必须包含与该记录原始证据一致的 `git+<仓库>@<已验证 Server 提交>` 和 `wheel-sha256:<已验证 Server wheel 摘要>`；相同 API 契约不能把另一构建视为已验证；`unqualified-candidate:...` 资源不能建立兼容性。发现接口返回的 Server 包版本须匹配固定资源版本。通过 `get_default_scope` 解析默认 Scope，再按返回的精确 ID 选择，无需手填 Scope ID 或复制本地 token。已有远程和认证连接保持独立，受保护配置可使用普通连接编辑器。仅复用地址和兼容配置完全相同的已保存连接，不会静默改写独立配置的目标或历史资格选择。保留既有的 20 个连接上限；必要时在连接页面移除不用的桌面配置，不会停止 Server 或删除数据。

停止服务、移除注册、移除 Desktop 和删除数据具有不同影响。本界面提供停止和移除注册，保留配置和数据，不提供删除数据操作。系统管理的服务独立于 Desktop 存活。退出后重开检查权威操作状态，不激活私有会话。

## 验证边界

UI 测试使用模拟的原生 IPC；原生连接测试使用合成 HTTP 发现和 Scope 响应；bridge 测试使用临时辅助进程和私有引用文件。这些验证本地契约行为，不等于已签名 Windows 11/macOS 干净机器安装、登录/重启、输入法、安装版读屏和凭据验收。后者由 #2108/#2109/#2112 使用确切发布资源和最终安装包验证；完整安装验收记录关联前保留 #2117。
