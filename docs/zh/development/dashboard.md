# Dashboard 设计原则

Dashboard 是 PowerContext 中供个人使用和演示的内容查看器，默认关闭，与 Server 共用访问模式：本地可免认证访问，启用认证时要求静态 token。这份文档供开发和评审人员判断页面该展示什么、如何组织阅读，以及一次改动是否保留了用户需要的行为。接口能力以 `openapi/powercontext.yaml` 和服务实现为依据。

## Dashboard 帮助用户完成什么

普通资料进入记忆的处理结果由 Atomic Memory 处理器持久化。“处理记录”读取每次尝试的输入、状态、已发布的精确版本，以及处理当时保存的模型说明。成功记录与记忆变更、消费进度在同一事务提交；失败和后续重试分别保留。重启后只有开始、没有结束的记录显示“完成状态待确认”，不能据此判断 Worker 仍在运行。

一次尝试可以处理多份资料。页面的结果汇总属于该批次，每条记忆的直接依据仍以其精确版本保存的来源为准。比较过程中的模型决定不等于最终发布结果；说明最多保存前 100 条，每条最多 2048 个字符，截短会明确标出。模型说明是 Scope 私有的历史材料，不是执行指令。读取记录需要 Scope 读取权限，以及所有披露输入、参与比较的制品和结果的读取权限。权限或读取失败不能显示为空历史。

直接写入时保存的内部 Source 通过服务端绑定的精确目标展示结果，不参与普通自动抽取。Working Note 同样不进入该流程。旧数据没有处理记录时保留未知，不能根据引用或当前配置补造形成原因。新增表通过 Server 迁移 `v1_4_1_005` 注册，不回填旧处理历史。现有数据库需在维护窗口通过统一迁移流程升级。

用户进入 Dashboard 时，可能想确认某项约定，查找解决过类似问题的经验，或继续一项中断的工作。页面需要让用户确定正在查看哪个范围，找到相关记录，并在需要时核对原始材料。

1.0 的核心是阅读已有内容。现有页面同时列出修订历史、比较两个修订，并通过接口已有的条件替换把某一份已保存修订写成新的当前版本。每条原子记忆可以查看和比较自己的修订，但只读。恢复原子记忆走它自己的恢复流程，确认前会预览所有受影响的记忆。记忆、经验、技能和交接可以分别存在：只有记忆的范围也应当能够正常使用；没有内容的范围仍有明确的入口和页面结构。生成、审核和保存由现有工具与接口完成，阅读这些结果不应要求用户先配置生成能力。

页面的业务主题来自范围名称、摘要和保存的内容。支付服务、客户访谈或个人研究可以使用同一套界面，不需要为每种业务另造导航。新增区块时，应先说明它帮助用户完成哪项工作，以及现有数据能否支持它表达的含义。

## 内容和范围的含义

### 各类内容回答的问题

| 内容 | 用户从中了解什么 |
| --- | --- |
| 记忆 | 已保存的约定、偏好、事实和决定 |
| 经验 | 某种情况下发生了什么，得到什么认识，以及适用条件和依据 |
| 技能 | 可以复用的做法、步骤和检查要求 |
| 交接 | 一次工作记录中的目标、进展和下一步 |
| 用量 | 上下文准备、投递与用户反馈记录，以及参考内容估算和 PowerContext 自身的模型用量 |

经验需要保留当时的情境，技能需要保留使用条件，交接表达的是保存时的状态。即使几份内容互有关联，阅读时仍需区分它们能支持什么判断。记录中关于修复完成的说法，需要通过相应依据核对。

首页和目录可以缩短摘要，详情保留完整正文。展示层负责呈现已有信息，不根据拆句或改写补出新的结论。来源引用帮助用户核对内容；有可读原文时提供入口，只有引用信息时如实保留引用。

### 范围决定正在看什么

范围（Scope）是内容归属和阅读选择的单位。未指定范围的入口使用服务端已配置的默认范围。用户在下拉栏选择另一范围，只改变这次浏览的位置，不改变默认保存位置或工具绑定。

名称相近的范围要能区分。选择器显示范围自身名称和已有的祖先关系，父子关系以服务端记录为准。父级内容不会自动进入子级目录；准备上下文时对其他范围的显式引用，也不等于父子归属。

内容目录和用量均读取当前范围，切换范围时一同更新。父范围的用量不自动包含子范围。例如，一个空子范围可以没有记忆，而父范围仍有记忆；这不构成数据缺失，也不能用父范围的内容填满子范围页面。

### 数据能支持怎样的判断

没有记录、没有可比较数据、服务未报告数值和读取失败，需要分别表达。只有接口明确返回零时才能显示零。无法读取某个范围或记录时，应说明失败并提供可用的恢复入口，不能静默换成另一份内容。

用量中的参考内容估算只覆盖可比较的记录。减少比例用于说明文本规模的变化，不代表信息完整性、内容质量或账单节省；估算结果为增加时也应如实展示。模型输入、输出和向量用量分别列出，缺报数值保留为未报告。

首页摘要、每日图表和明细表采用同一统计口径。周期和每日归属来自服务端，界面不补造历史数据。

## 页面如何组织阅读

### 首页提供概览和入口

首页先显示当前范围；存在受阻、失败、未确认结果或读取故障时，异常问题位于全部数据之前。普通待处理和待审核不视为异常。其后依次为四个浅蓝概览框、Token用量、有数据时的交接、资料处理明细、已保存内容明细和上下文准备明细。三个明细区各显示最多三条，通过目录入口查看更多，不在首页折叠展开其余记录。Token用量和用量页共享完整比较组件，包含相同的纵轴、网格、图例、统计口径和提示。

四个概览框分别展示累计保存资料、六类产物汇总、待审核候选和所选周期的上下文准备记录。数量来自统计契约，不从首页预览条数推算。制品库存与准备记录采用不同时间口径；它们不是同一批资料的转化漏斗，也不能证明 Agent 采用或任务收益。待审核计数包含制品和标签变更候选，入口使用全部候选的待审核筛选。各类制品库存包含其当前 head 的全部生命周期状态，进入目录后仍按该目录的既有筛选浏览。

内置 Runtime 在已授权、已审计的页面 snapshot 内读取库存，不为首页额外加载复发历史。库存与用量独立读取和显示错误；一项不可用时，另一项和已有内容仍可阅读。切换用量周期不改变库存，切换范围则同时更新全部概览信息。

每个区块有明确的标题和查看入口，摘要只承担预览作用。宽屏将近期处理与近期保存内容并排呈现，窄屏按同一阅读顺序排列。标题取自已保存的内容字段；技术身份与原始数据不作为业务标题。某类内容尚未生成时，空状态留在它所属的区块中。

用户也可以从目录、收藏链接或精确引用直接打开记录。

### 目录用于查找，详情用于阅读

目录帮助用户辨认并选择条目。长列表通过分页控制一次需要浏览的内容，搜索帮助缩小查找范围。搜索的范围和结果上限需要与接口一致；当前一页的筛选不能表现为整个内容库的搜索。

记忆采用目录与正文的阅读方式。经验、技能和交接从目录进入详情，详情承载完整内容和关联材料。条目较多时，摘要可以截短，但用户始终有路径读到全文。

记忆的精确链接保留桌面左侧列表，并在右侧展示所选不可变版本。点击条目在当前页面替换记忆区域，URL 保留生命周期筛选、周期与分页。小屏幕保留折叠列表；只有制品读取权限时保留独立详情，不展示无权读取的 Scope 目录。来源关联校验、未记录的历史原因和版本比较保持现有行为。画像页使用与其他主页面相同的外层内容宽度。

用户打开一条记录后，应能返回所属目录。更换搜索条件从第一页开始；切换范围清除上一范围的记录选择和分页位置，详情返回对应目录。单纯切换语言或主题则保留范围、周期和正在阅读的记录。

记忆搜索默认遵循部署能力，也允许用户选择检索模式。展示实际模式、每条结果的命中通道与检索得分，帮助用户核对召回依据；得分不解释为相似度百分比。

### 处理记录连接资料与已有结果

处理页默认展示所选周期的总览：输入处理完成数、成功投递回执、明确采用，以及需要关注的未完成输入和未知采用情况。数字来自 `GET /v1/scopes/{scope_id}/processing/summary`。各阶段独立计数，不是同一批资料的转化率。成功投递只计本周期创建、当前状态为 `injected` 的 Bootstrap 回执；准备完成、待确认和失败回执不计成功投递。采用与未知采用按本周期创建的每条准备或 Bootstrap 记录在窗口结束前的最新反馈统计；重复或修改反馈不累加采用次数。

自动处理页签保留逐次记录，资料与执行页签分别查阅输入和 Dream。成功重试不删除原失败；失败历史单独展开，不把已成功的输入继续列为未完成。当前待完成输入包括没有尝试的资料，以及失败或未确认完成记录已在所选周期之外、但仍未消费的资料。本周期已有尝试的输入保留在对应状态计数中。扫描达到上限时，即使当前下界为零，也不能认定没有积压。

记忆详情统计所选精确版本在本周期被纳入上下文准备的次数和最近准备时间，包括其他 Scope 发起的准备。只有当前用户可读取准备所属 Scope 和全部所含制品时，该记录才计入次数和时间。数据库在周期内按保存的条目地址筛选；条目地址尚无索引，查询工作量会随准备历史增长。这些数字不能证明投递、采用或帮助。

处理记录分别提供公开 Content Source 资料与 Dream 执行的分页目录。内置资料目录按保存位置从新到旧排列；其他 Runtime 保留公开接口提供的顺序。Dream 按受理时间从新到旧排列，并支持状态筛选。两个目录都只读取当前 Scope。资料已保存不能证明处理成功或生成了新内容。

资料详情显示保存内容，以及最多 20 个直接引用它的精确制品版本；超过上限时明确提示。这个查询说明引用关系，不重建执行历史。内置 Runtime 在授权和审计快照内读取关联身份，不解码整个制品集合。结果数量有上限，但当前来源引用表没有按来源建立的辅助索引，数据库工作量会随 Scope 内引用行数增加。其他 Runtime 未提供关联查询时显示不可用，不能显示成空结果。

Dream 详情显示保存的状态、结果、原因、尝试次数和时间，以及输入清单和候选入口。是否发布及当前审核状态仍在审核收件箱核对。输入清单中的节点可以提供已解析的上游资料引用；整次执行的输入不自动成为每个输出的直接依据。没有保存的逐次尝试时间、错误和历史不补写。此处只覆盖已有 Dream 记录，不代表全部资料自动处理流程。

### 审核说明候选内容与已保存结果

候选目录使用已有变更说明和类型名称，打开后可用已保存的业务内容作为标题。内置目录继续只读轻量元数据，不为了标题加载全部候选正文。详情先展示可读字段，原始数据放到展开区。修改候选与它记录的目标版本对照，该版本不一定仍是当前版本。目标读取失败时显示无法对照，不能伪装成未修改或原内容为空。

依据正文与候选历史仍由用户显式展开后读取。完整提案、原始差异、打包信息和完整版本编辑器均保留。批准后的影响与候选说明、依据分别呈现。所有决定仍由原有接口检查当前权限、同来源请求和候选版本。

决定完成后按保存状态打开同一候选，保留语言、Scope 和统计周期。已批准内容直接链接到决定记录的精确结果版本，即使后来已有更高版本也不替换该链接。标签变更展示批准时保存的标签及所依据的内容版本，不产生内容修订，也不证明这些标签至今未被修改。

### 使用记录区分准备、投递与用户报告

用量页保留资源统计，并提供独立的使用记录页签。准备明细保存所含内容的 Scope 和精确版本、字节数、截断与降级状态，不保存查询或正文。只有启用 Dashboard 的内置 Server 记录后续准备；未配置的 SDK 不增加这项存储。已有 Bootstrap 回执按原状态展示。旧的聚合统计不能补成逐次历史。

打开明细后可以阅读当次引用的版本，再返回原记录，保留周期和语言。跨 Scope 内容返回其准备记录所在的 Scope；该返回入口不授予权限，目标页面仍独立授权。用户分别报告是否采用、是否有帮助和说明；反馈标明报告身份与时间，不由任务成功或上下文投递推断。具备当前 Scope 贡献权限并可读全部引用内容的用户可以提交反馈。写入保留同来源检查和幂等身份；重复提交同一内容不追加记录，相同身份提交不同内容返回冲突。修改反馈产生新记录，展示采用最新一条。

准备和反馈使用内置授权、审计快照与持久化能力；`POST /dashboard/usage/feedback` 是页面表单操作，不是新增公开 JSON API。增量迁移 `v1_4_1_006` 添加准备与反馈表，不回填过去的查询和正文。交接详情只关联其精确版本的接收记录，以及明确引用该接收记录的任务结果；这些是接收方的报告，不证明记忆带来了任务收益。

### 原始材料支持就地核对

读者可以从记忆、经验、技能或交接直接打开对应原始材料。材料使用 Tabler 原生大尺寸弹窗阅读，小屏全屏显示；多份材料通过选单切换。关闭后回到原记录的阅读位置，键盘用户也能完成同样的过程。

材料正文可能很长。阅读区域根据视口分配空间，标题和关闭操作保持可达，正文在该区域内滚动。打开一份材料不应把整页推长到用户找不到原来的位置。某份材料读取失败时，已经打开的记录仍可阅读。

## 范围、权限与读取结果

未显式选择范围时，页面使用默认 Scope；本次读取确定范围后，默认绑定的切换只影响后续请求。查看其他范围不会修改默认绑定。选择默认 Scope 需要 `server.observe`，读取范围内容仍需相应内容权限；Observer 权限本身不授予内容访问。

有 Scope 读取权限时，可以浏览该范围的目录与用量。只有单项 Artifact 读取权限时，只能打开获准记录的精确版本及其引用，页面不显示 Scope 标题、相邻记录或范围用量。有效 grant 不因缺少 owner relation 而失效；owner 自身的权限仍须有真实 relation。撤销的权限不会因页面重试而恢复，详见 [Artifact ownership](../rfcs/1396_handoff_access_control.md#artifact-ownership)。

精确链接的正文和引用始终对应请求的 Revision。当前版本与生命周期状态单独显示，历史正文不能被标为当前正文。同一响应中的正文、状态和授权结果须保持一致；后续请求按新的权限和内容状态重新判断。

Home 的记忆、交接、经验和技能可以独立阅读。一类内容缺失或读取失败时，其余可读分区仍显示；用量不可用时，页面保留已授权的范围信息和可读正文。读取失败应显示错误，不能伪装成空列表或零用量。正文和范围元数据只有在相应授权与必要审计完成后才可显示。

搜索或浏览没有返回记录，不代表其精确历史版本不存在。已有精确引用仍按当前权限读取；重建搜索或浏览数据不能改写历史正文、引用和版本身份。页面读取不补建 owner，也不修复失效的默认绑定；需要恢复时使用相应的维护操作。

范围选择器支持分页与检索，当前范围不因其他范围未加载而失去可读性。Review 先展示候选目录，正文随选择打开；历史和证据正文由读者显式打开。

打开记录时保留所选版本的原文，并展示分页的修订历史。版本比较展示选中的两个版本；比较失败不会替换已打开的正文。历史、比较和回滚操作遵循当前权限。回滚会创建新版本并记录来源、原因和操作者；当前版本并发变化时，用户需要先检查新的当前版本再重试。

## 布局与交互如何保持一致

### 内容变化不改变页面的组织方式

有内容、无内容和搜索无结果时，页面保留相同的标题层级、主要分区和阅读顺序。记忆目录不会因为暂时为空就变成另一种整页视图，用量也不会因为没有记录就丢掉统计区域。

稳定布局需要保留必要的阅读空间，但不要求所有状态像素级等高。预留高度应考虑摘要容量、分页容量和可用视口；长正文可以自然增高。末页条目变少时，分页操作保持容易找到的位置。内容不足一屏时，正文起点也不应向下漂移。

### 根据阅读空间选择分栏和滚动

页面容器、两侧留白和栅格间距沿用 Tabler 的默认规则。分栏的前提是两侧都有足够的阅读宽度；空间不足时按顺序堆叠，不通过缩小正文字号维持分屏。

小屏上的记忆在条目内展开，打开另一条时收起上一条；桌面使用目录与正文分栏。搜索结果沿用同样的阅读方式，上一页、页码和下一页保持可见，没有可翻阅的页面时禁用对应操作。

列表通常随页面滚动，一页中的条目应直接可见。局部滚动用于需要保持上下文的长正文、材料面板或宽表格。是否增加滚动区域，要看它能否帮助用户保留阅读位置；不能仅为了让卡片看起来整齐而嵌套滚动条。

### 文案和视觉共同表达层级

标题说明页面或区块的内容，按钮说明执行的操作。业务正文保持原文，界面文案使用直接、具体的表达。用户已经能从导航和内容判断的信息，不需要再用说明文字重复。

字体、字重、按钮和表单状态优先采用 Tabler 的默认选择。记忆、经验和技能条目使用常规字重，避免每条内容都争夺注意力。同一层级的卡片使用一致的边界和间距，箭头用于有方向含义的操作。

中英文和明暗主题适用于全部 Dashboard 页面，包括登录与独立材料页。翻译可以自然换行，但不应打乱导航顺序、按钮分组或主栏比例。主题切换保留相同的信息层级和可读性；业务内容不随界面语言改写。完整 Logo 使用现有品牌资源，favicon 只使用图形部分。

## 启用与访问

通过 `POWERCONTEXT_SERVER_DASHBOARD_ENABLED=true` 启用 Dashboard。本地 `ACCESS_MODE=disabled` 时直接访问，无需 token；`ACCESS_MODE=enforced` 时要求 `AUTH_TOKEN`，使用内置静态 Bearer 身份，所有 token 持有者共享同一权限。注入认证或授权 Provider 的团队部署必须关闭它。页面遵循服务的访问模式和当前权限，不提供成员或角色管理。个人启用步骤见[安装和运行](../docs/get-started/install-and-run.md)。

## 可见行为验收

| 场景 | 验收关注点 |
| --- | --- |
| 首次使用、仅有一种内容、搜索无结果 | 状态准确，主要布局与入口仍可辨认 |
| 默认范围、同名范围、空子范围和显式引用 | 阅读与统计边界明确，切换不改写默认值 |
| 长列表、末页、长材料和小视口 | 条目可遍历，全文可读，操作可达，阅读位置合理 |
| 切换语言、主题或返回历史页面 | 范围、记录身份和信息层级保持一致 |
| 缺报用量、不可比较数据、部分读取失败 | 用户不会把未知理解成零，也不会把失败理解成空内容 |
| 凭据失效、网络中断和服务恢复 | 错误明确，重新登录或重试后可以继续读取 |

### 页面与接口

| 记忆目录与正文 | `POST /v1/atomic-memory/list`、`POST /v1/memory/search`、Atomic Memory 精确版本与状态读取 | 保留独立制品身份、生命周期筛选、搜索模式与命中依据；最多 50 条匹配结果 |

| 经验目录与正文 | `GET /v1/scopes/{scope_id}/artifacts/experience`、`POST /v1/experience/get`、`POST /v1/scopes/{scope_id}/artifacts/experience/search` | Dashboard 提供分页浏览与 Family 相关性搜索；搜索只覆盖 approved 且 active 的当前版本，最多返回 200 条，达到上限时提示缩小查询 |

| 处理记录 | `GET /v1/scopes/{scope_id}/processing`、`GET /v1/scopes/{scope_id}/processing/summary`、资料处理历史、资料与 Dream 目录和精确读取 | 保留各自游标顺序、保存状态和已记录结果；不推断缺失的尝试或结果 |

首页显示当前范围的记忆、交接、经验、技能和用量摘要。目录显示可读条目及翻页入口，不推算未经报告的总数。记录和材料引用保留完整身份。

### 观测与首页概况

异常区直接列出已知原因、最近错误、影响和排查方法；原因缺失明确显示未知。重试上限只解释停止重试，不证明最初失败的原因。主题记忆受阻入口定位到处理总览中的同一份诊断，保留错误码、受阻时间和尝试次数。手机明细保持时间、结果与输入可读，页面不出现横向溢出。

侧栏分别提供“观测”“检索与使用”和“运行状态”入口。“观测”页包含总览与处理记录。原有 `/dashboard/processing` 和 `/dashboard/usage` 链接继续有效。总览与自动处理使用和用量一致的 UTC 日历周期；选择具体处理日期后，以该日期为准。资料库存与 Dream 执行历史不按周期筛选，因此不显示周期选择器。

总览显示具体 UTC 统计范围。没有处理记录时，页面说明历史无法确认，不用零计数表示缺失的证据。

`/dashboard/runtime` 与其他页面使用相同的 Dashboard 身份验证，但不要求选择内容范围。页面读取当前服务实例已有的 `/health/live` 和 `/health/ready` 契约。就绪检查返回 HTTP 503 时显示未就绪；检查读取失败时显示暂时不可检查。这些结果不证明所有 Worker 或指标、日志、Trace 链路正常。访问控制覆盖放在次要详情中，与依赖健康分开显示。

处理总览与自动处理还支持近 90 天和自定义起止日期。开始和结束当天均计入 UTC 统计，范围最多 92 天。所选日期在处理页签、状态筛选、内容范围切换和翻页时保留。日期无效或顺序错误时，可以直接修改表单。检索与用量统计沿用其已有的周期选项。

### 首页与处理总览的数据分工

首页保留当前库存和使用摘要。处理总览不再读取或重复库存、上下文准备和采用计数。总览分别展示有处理记录的资料、完成的资料、记忆变更和完成但无变更的执行次数；这些数字不构成转化漏斗。没有处理记录时显示历史无法确认，不显示全零结果或正常结论。资料记录与后台整理任务提供独立入口。

当前排队、运行和重试状态尚未完整接入；完成待确认不代表 Worker 仍在运行。待处理扫描仍排除所选周期已有尝试的资料，保留扫描上限提示，不能称为完整实时队列。

处理总览通过已授权的公共状态接口读取当前主题记忆状态，不受历史日期窗口限制。页面区分无待处理窗口、有待处理工作和受阻，不把待处理视为 Worker 正在运行。受阻技术详情可展开。内置运行时直接显示最近六份资料、经授权的处理摘要和精确资料历史入口；资料位置差不当作待处理数量。

使用记录详情先显示已保存的结果和原因，再显示本次准备的精确内容。投递说明只用于投递记录。已有反馈直接可见；可选反馈表单默认折叠。记录编号、调用入口和参考内容大小放在带字段名称的可展开详情中。

自动处理列表每次最多展示三份经授权的原文摘录，再展示保存的处理结果和起止时间。更多输入显示剩余数量，content 资料可进入原文和处理详情。原文读取失败时明确显示不可读，不以其他内容替代。资料位置区间和统计明细收进辅助详情，不再作为记录标题。

资料详情使用三个编号步骤：保存的输入、已记录的处理、保存的输出。缺失的执行历史保留为未知。引用该资料的内容与当前执行的直接产出分开显示；引用关系不能证明执行时间或新增行为。

资料编号与完整原文归入输入步骤，执行记录入口归入处理步骤，引用版本归入输出步骤。删除底部独立技术详情区域；更多引用版本在输出步骤内展开。

`record_type=dreams` 的页面名称为“Dream 任务记录”，包括经验、技能和其他受支持内容的提炼或修订任务。无状态筛选时区分暂无已受理任务；有筛选时说明当前状态无匹配记录，并提供普通资料“自动处理”入口。

首页近期处理结果按“时间、结果、用户输入”三列展示。用户输入摘录链接到精确资料处理详情；批次说明归入结果列。

近期保存的内容按“时间、类型与版本、内容”三列对齐展示，保留前三条和其余内容的展开入口。

### 手动生成经验与 Skill

经验与技能页面提供“生成经验”和“生成 Skill”入口。用户选择当前 Scope 的精确依据，提交当前页勾选项。经验支持资料、有效记忆版本和正式经验；Skill 支持资料或正式经验，按选择匹配来源类型。补充说明仅作为候选元数据保存。

Dashboard 使用当前凭据调用已有 Generate 接口，并要求请求同源。生成后不会自动审核：待审核候选进入审核收件箱，未生成候选时明确提示。等待上限为 120 秒，不自动重试。直接 Generate 不会创建 Dream 执行记录。

经验与技能共用一个侧栏入口，保留内部类型页签和各自生成按钮。“检索与使用”作为“观测与配置”下的独立侧栏入口，直接打开使用记录。观测页保留总览和处理记录页签，不再嵌套“检索与使用”。

使用记录列表按“时间、结果、召回数量、详情”四列展示。数量来自已保存的选择，列表不读取内容原文；点击详情后，以编号表格读取并展示经授权的精确内容版本。空选择显示 0 项内容；截断记录保留完整性提示。不重建未保存的原始提问。

“Token用量”与“检索与使用”是独立的侧栏入口，不再通过页面内部页签切换。切换 Scope 时保留当前视图。

使用记录详情把召回内容按“序号、召回内容、类型、版本、保存时间”列成表格。正文使用普通文字，精确版本的详情链接单独保留。保存时间使用所引用版本的时间，缺失时显示“未记录”，不使用本次准备时间代替。较长正文可展开。

当前画像与空画像页面提供“生成画像”按钮，调用现有 `/v1/profile/flush` 接口，按现有生成与生效策略处理下一批资料。更新、无变化、未启用及冲突分别提示；待审核候选进入审核页面。历史版本不显示生成按钮。操作保留 Scope 授权及同源检查。

记忆召回排序使用 `POST /v1/atomic-memory/list`，参数为 `sort_by: recall_count` 和 `period: today | 7d | 30d`。API 默认仍按 `identity` 排序；Dashboard 默认“召回最多”，并提供编号顺序选项。响应 `recall_counts` 给出当前页记忆标识到已记录上下文准备次数的映射。同一记忆合并所有版本，每次准备对同一标识只计一次。仅统计用户能读取准备所属 Scope 及全部所选制品的记录，包括已授权的跨 Scope 使用。后端先全局排序再分页，次数相同时按标识排序；游标绑定筛选、日期、用户及首屏准备记录截止时间。搜索保留相关性排序，详情统计仍针对打开的精确版本。

排序读取符合筛选条件的记忆标识及周期内相关准备记录，不解码全体记忆正文。M 个候选标识的排序复杂度为 O(M log M)，另需校验相关准备记录的权限；这不是固定成本的索引排行榜。本地 SQLite 样本包含 1,000 条当前记忆和 200 次准备，返回六项耗时 0.372 秒，不代表 OceanBase 或更大历史规模的性能。

左侧“自动处理”直接进入资料主表（`record_type=sources`），每行是一份资料。“执行记录”为页内辅助视图（`record_type=attempts`），保留所选周期的四个处理汇总框、状态筛选及完整执行历史；首页只保留近期明细与入口。旧总览链接继续可读，并可按锚点定位当前主题记忆受阻诊断。

侧栏顺序为首页、运行时数据（自动处理、Dream 处理）、已保存内容、日常工作、观测、配置。首页不提供局部日期选项，当前周期保留为文字。记忆目录展示全部符合状态或搜索条件的内容，不按时间筛选，也不显示周期文字。召回统计仍采用请求周期。记忆目录在编号顺序、召回排序、搜索及非在役筛选下均保留召回次数行。服务端通过现有列表 API 的有界 `artifact_ids` 筛选批量读取当前页身份的计数；计数不完整或不可用时显示未知，不当作零。桌面摘要固定预留两行，切换排序时元信息行不会消失。

首页全量处理汇总由内置读取投影提供，公开处理汇总 API 仍保留近 7 天默认值和最多 92 天的查询范围。全量汇总解码本 Scope 的全部执行历史，成本随历史记录数增长；仅支持公开 API 的注入应用显示统计不可用，不用近 7 天数据冒充全量。

首页四个浅蓝概览框分别展示已保存资料、六类产物汇总、待审核候选、周期内上下文准备次数。产物汇总保留各目录数量与入口。资料处理页的四个卡片展示处理完成、记忆变更、尚无成功记录的资料和结果未确认的资料，跟随该页筛选范围。手机上每行两格。

资料处理的自动处理记录采用时间、处理类型、原文、处理结果和操作五列表格。详情在当前行下方展开，保留已记录的决策原因、精确产物版本、原文入口、开始与结束时间、失败阶段、错误码和记录身份。处理类型为记忆处理；存在上次执行身份时标明重试，不推断缺失的触发原因。窄屏在表格区域内横向滚动。

资料主表使用原文、当前处理结果、最近处理时间、处理次数与详情五列。处理次数通过既有授权历史接口读取当前页最多六份资料各二十条记录；存在下一页时显示 20+，读取失败显示未知，空历史显示未记录，不推断从未处理。公开资料记录没有保存时间字段，因此不得把处理时间标作保存时间；没有已记录时间时显示未知。处理汇总将新增与更新放入记忆变更框，把执行总次数及无变更次数放入完成框，把历史失败执行次数放入尚无成功记录资料框；资料数量与执行次数分别标注，保留重试成功后历史失败仍存在的事实。移除重复的统计明细折叠区。页面说明仅承诺资料原文、处理结果与异常原因；上下文准备、投递及反馈在检索与使用页核对，不证明 Agent 采用。

运行时数据分组提供自动处理和 Dream 处理两个入口。自动处理内可切换资料和执行记录，二者共享标题及侧栏选中态。复用已有 processing 路由的 sources、attempts、dreams 参数，保留旧链接。执行记录和 Dream 处理在标题旁提供可悬停或键盘聚焦的说明。切换 Scope 保留当前记录类型，跳转平级入口清除上一目录的游标、详情身份和筛选。局部导航同步更新浏览器标题。

资料处理详情统一采用 h1 24px、h2 20px、h3 18px、h4 16px，正文 14px、辅助信息 12px。页面只保留一个 h1；步骤内的结果和原因使用下级标题。之前的处理采用同一字号、间距及卡片边框，展开历史记录不切换成另一套排版，移动端保留相同层级。

资料输出使用内容、类型、版本与详情四列表格，主题记忆显示已保存的标题和摘要。正文按精确 family/artifact_id/revision 读取，优先当前执行和关联产物，最多读取 20 份预览；读取失败或超过预览预算时显示不可读与具体身份，不用资料原文替代产物内容。直接输出、保留记忆和仅引用该资料的关联产物仍分别展示，引用关系不推断为本次创建。之前的处理采用简洁的输入、处理、输出三段；默认只展示短原文、首条原因或错误，以及最多三项产物，额外结果和完整记录按需展开。

资料详情使用原始数据输入、处理原因、处理结果三个 H2 卡片标题，标题栏按步骤使用不同深浅的蓝色背景。第二框只保留原因，保存数量和产物表格放在第三框；执行元信息放在三框之后按需展开。仅引用该资料的关联产物默认折叠，保留数量及引用关系说明。

经验与技能默认通过生成经验／技能入口创建异步任务，选择内容后用发起任务提交；打开选择面板时不重复显示入口或下方目录，依据类型切换自动加载，选择数量在提交区显示。同步生成保留为次要入口，并说明等待结果、不创建Dream记录。经验从精确版本的记忆或经验发起 refine_experience，技能从经验发起 derive_skill。复用既有 Dream API，不把仅有原始资料的同步 Generate 请求伪装成 Dream。提交表单使用幂等键，跳转任务详情；排队和执行期间每三秒刷新，终态停止刷新，候选仍需审核。原始资料的同步生成保留。请求成功受理后才有Dream任务记录，受理前的校验失败不产生任务。

首页及处理页受阻诊断提供重试处理按钮，提交当前 block_id。既有恢复接口负责 scope.admin 授权、幂等受理及过期记录冲突；Dashboard 额外检查同源请求、限制表单大小并保留后端错误状态。受理后显示后台请求已提交，不宣称处理完成，也不自动重试其他 Scope。

侧栏图标使用 Tabler Icons v3.35.0 的本地 SVG，沿用线条和尺寸。自动处理用自动化设置、Dream 用星月、记忆用脑、主题记忆用层级、经验技能用工具、画像用用户扫描、审核用检查清单、交接用双向箭头、检索用放大镜、Token 用量用硬币、运行状态用脉冲、提示词用调节控件，各入口图标不同。

运行状态页的配置区来自当前 Server 组装时使用的 BuiltinConfig 白名单快照，通过 Dashboard HTML 返回，没有新增独立公共 JSON 配置接口。显示服务角色、显式 Dream 开关、记忆/主题记忆/经验自动调度周期、画像 cron 与时区、模型配置状态及并发/超时。不会读取磁盘环境文件或根据源码默认值补齐未知配置，不包含凭据、模型 URL 或数据库路径。健康状态仍通过 /health/live 和 /health/ready 获取。配置开启不证明任务正在执行；只读数据库游标属于排查证据，不属于本配置区的数据源。
