# 发布博客

提供 Markdown 文件或正文即可。发布流程会补齐中英文版本，整理稳定的 slug 与摘要，复用已有作者资料，并一起检查两种语言。新作者需要真实姓名和照片，简介及社交账号按已确认的信息填写，这些信息不会凭空编造。整理好文章不代表已经部署官网。

转载或整理文章时，删除原渠道的公众号关注、扫码入群、订阅导流文案及配套二维码；保留与正文相关的技术链接和来源引用。

## 文件位置

- 中文：`docs/zh/blog/posts/<slug>.md`
- 英文：`docs/en/blog/posts/<slug>.md`
- 作者资料：`docs/zh/blog/.authors.yml` 与 `docs/en/blog/.authors.yml`
- 共用照片和文章图片：`docs/assets/blog/`

中英文文章的相对路径、slug、发布和更新日期、作者 ID、草稿状态、置顶状态必须一致。标题、摘要、正文、分类名称和作者简介分别本地化；代码、命令、链接与技术含义忠实保留。

```yaml
---
title: 文章标题
description: 用于博客列表的简短摘要。
slug: article-slug
date: 2026-10-23
updated: 2026-10-24
authors:
  - jackie-cqz
categories:
  - 工程实践
cover: assets/blog/article-slug/cover.png
cover_alt: 项目上下文跨会话延续的插画
draft: true
pin: false
---
```

元数据下方直接写普通 Markdown。开头的一级标题可省略，网页只显示一次文章标题。正文图片可写为 `../../../assets/blog/article-slug/image.png`，作者照片路径写为 `assets/blog/authors/name.jpg`。每位作者以独立 ID 登记，姓名、简介和头像分别保存在 `name`、`description` 和 `avatar` 中。所属组织、团队或贡献者身份直接写在各自的 `description` 中，不设置统一团队归属。作者尚未确认的草稿可使用 `authors: []`；发布前必须填写真实作者 ID。

## 作者社交账号

社交账号单独放在 `socials` 下，与可选的作者简介分开。文章顶部和作者页显示平台图标与可点击的 `@账号`。只填写已确认的账号，未知账号省略，中英文必须一致。填写账号 ID，不填完整链接；开头的 `@` 可省略。

```yaml
authors:
  jingshun:
    name: Tanner
    avatar: assets/blog/authors/jingshun.jpg
    socials:
      github: hidb4ai
```

作者有 X 账号时，在 `socials` 下增加 `x: 实际账号`。职位、所属组织等信息写在 `description` 中。

## 文章封面

页面采用统一的 16:9 封面版式：顶部 16% 为品牌区域，下方 84% 完整展示插画。透明 PowerContext Logo 由组件自动添加，不与插画重叠。请提供不含 Logo 的封面素材，中英文列表和文章页共用此版式。

每篇已发布文章必须提供封面和有意义的替代文本，草稿可以暂缺。建议使用与主题相关、无内嵌标题的 16:9 插画，推荐尺寸为 1600 × 900。中英文共用相同的 `cover` 路径，分别本地化 `cover_alt`。图片保存于 `docs/assets/blog/<slug>/`；缺少文件或封面字段时，构建会阻止发布。

封面用于首页重点文章、文章列表、文章顶部及分享预览。正文配图按内容需要添加，不规定数量。提供的文章没有合适封面时，由发布流程补齐，不自动取正文第一张图代替。

## 正文配图与语言

不含文字的封面和插画可由中英文共用。含有说明文字的流程图、架构图和图表必须按语言提供两份素材，例如 `.zh.svg` 与 `.en.svg`，并在各语言 Markdown 中引用对应文件。两版保持相同的数据、流程、配色与布局；API、代码标识符和产品名保留原文。章节标题使用 Markdown 文字，不使用标题图片。

## 排列、分页与作者页

已发布文章自动进入列表，按日期倒序排列，置顶文章优先。每页 10 篇，作者页和年份归档也自动分页。草稿和未来日期的文章不会进入公开构建；定时文章需要在发布日期重新构建后才能上线。

- 博客：`/zh/blog/` 与 `/en/blog/`
- 文章：`/<语言>/blog/<slug>/`
- 后续分页：`/<语言>/blog/page/2/`
- 作者：`/<语言>/blog/authors/<作者 ID>/`
- 归档：`/<语言>/blog/archive/<年份>/`

博客复用官网原来的导航、语言切换、主题与页脚，博客样式只作用于博客页面。新增文章无需修改首页组件或导航列表。

## 预览与检查

在仓库根目录运行 `make docs`。修改正文后重启预览，以重新生成 Markdown 内容。请打开 HTTP 预览地址，源模板不是可以直接打开的网页。

交付前运行：

```bash
make docs-test
uv run pytest tests/e2e/test_blog_site.py -q
```

构建会检查双语对应关系、元数据、作者引用、分页、静态页面及内部链接。只有明确要求部署时才发布到官网。


明确要求使用原文配图时，中英文均保留原图，分别提供本地化替代文本与图注。MiniMax Code 文章使用 OceanBase 原文的九张配图。

自然语言提示词、代码注释、示例问题以及站内链接的目标语言必须与文章一致。可执行语法、API 标识符和产品名保持原样。真实产品截图可以保留原界面语言，但必须配备本地化替代文本和说明，标明原始截图。发布前同时检查 Markdown 和图片内的文字。
