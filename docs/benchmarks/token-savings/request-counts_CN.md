这轮独立的 24 题实验中，MS 的主模型请求为 **539 次，OFF 为 708 次，减少 23.87%**。两组都解出了相同的 15 题，各有 24 条技术有效记录。

| 组别 | 主模型请求 | 完成响应 | 每题平均请求 | 解出题数 | 技术有效 |
| --- | ---: | ---: | ---: | ---: | ---: |
| OFF | 708 | 708 | 29.50 | 15/24 | 24/24 |
| MS | 539 | 538 | 22.46 | 15/24 | 24/24 |

降幅按全部 24 题的总数计算：`(708 − 539) / 708 × 100 = 23.87%`。MS 的未舍入平均值为 `539 / 24 = 22.458333…`。

## 计数口径

这里的一次请求，是观测到的一次主模型物理请求，不是工具调用次数、用户对话轮数或 reasoning token 数。MS 的计数保留了 1 次没有完成响应的请求：第 388 题有 25 次请求、24 次完成响应。服务商内部不可见的重试次数仍然未知。

记忆生成、embedding 等辅助请求不计入主模型请求。因此，这个数字不代表所有模型调用或系统工作的总量。

## 实验条件与结论范围

本实验将 OFF 定义为 M/C/S 均关闭；MS 为 Memory 加显式工作指导（Steering），CodeGraph 关闭。MS 复用了历史记忆种子。原报告将历史种子的生成、探索和 embedding 开销与本轮新增开销分开列示；这些开销均未计入上面的请求数。

每个组别、每道题都使用状态记录选定的唯一 `r1` 结果，不按成功与否或 token 数挑选。全部 48 条选定记录均已纳入，原报告没有额外执行记录。[JSON 数据](request-counts-24.json)保留了逐题编号、组别、请求数、完成响应数、结果、有效性和 outcome 哈希。

本轮使用的 24 个题号与[此前 OFF/MCS token 对比](README_CN.md)相同，但属于**不同运行、不同配置**。此前的 token 减少 32.57%、解出 16/24 题不适用于本轮 OFF/MS。请求数减少不能据此换算为耗时减少，也不能证明其他任务上的质量相同，或把差异单独归因于 Memory 或 Steering。
