# 验证样例

> 环境准备好之后（`README.md` 第 2 节），按顺序执行下面的样例即可核对主要功能，
> 以及 seekdb / PowerContext 各自在哪一步真正发挥作用。
> 每一步都给出：初始数据 → 输入 → 操作 → 预期结果 → 技术参与的证据。

---

## 样例 0：系统就绪自检 + 一键全流程

| 项 | 内容 |
| --- | --- |
| 操作 | `cd qoder && python -m syncrecall health`（需先 `pip install -e .`）或 `cd qoder && python verify.py` |
| 预期 | `seekdb.ok = true`，`seekdb.version = 5.7.25-OceanBase seekdb-v1.4.0.0`；`powercontext.ok = true` 且 `status = ready`；`embedding.provider` 显示当前嵌入方式 |
| 证据 | `logs/02-health.log`、`logs/09-verify.log` |
| 失败排查 | seekdb 不可达 → 检查容器与 2881 端口；PowerContext 不可达 → 检查 18080 与 `powercontext server run` |

> `python verify.py` 会把下面样例 1、2、3、4 的内容串成一次运行，并打印两次排名对比，
> 评审只想看结论时可以只跑它。

## 样例 1：导入初始数据（21 条资料 + 60 道复习题）

| 项 | 内容 |
| --- | --- |
| 初始数据 | `qoder/data/seed.json`：课程笔记 15 条、论文 4 篇（Raft / Paxos Made Simple / Bw-Tree / 分布式并发控制）、群聊 2 条、会议纪要 1 条；覆盖 分布式系统 / 数据库系统 / 软件工程 三门课 |
| 操作 | `python -m syncrecall seed --reset` |
| 预期输出 | `{"notes": 21, "cards": 60, "papers": 4, "embedder": "hash-ngram"}`（装了 sentence-transformers 时 `embedder` 为 `sentence-transformers:paraphrase-multilingual-MiniLM-L12-v2`） |
| 技术参与 | **seekdb**：自动建库建表，写入 `note.embedding`（VECTOR）与 `review_card`（SM-2 初始排期） |
| 核对 | `SHOW INDEX FROM syncrecall.note;` 应看到 `ft_note`（FULLTEXT）与 `vidx_note`（VECTOR）→ `logs/04-indexes.log` |

## 样例 2：混合检索（seekdb 单条 SQL）

| 项 | 内容 |
| --- | --- |
| 初始数据 | 样例 1 已导入 |
| 输入 | 问题：`Raft 怎么保证不丢已提交的日志` |
| 操作 | `python -m syncrecall recall "Raft 怎么保证不丢已提交的日志"` |
| 预期 | 返回命中列表（含 `fts_score` / `vec_score` / `score`），Top 中出现《Raft 日志复制与提交规则》与《论文精读：Raft 与 Paxos 到底是什么关系》；输出末尾打印实际执行的完整 SQL；`memory events` 里依次出现「PowerContext 读取检索偏好 → seekdb 混合检索 → PowerContext 写回会话交接」 |
| 技术参与 | **seekdb**：`MATCH ... AGAINST`（`ik` 全文）与 `cosine_distance ... APPROXIMATE`（HNSW 向量）在同一条 SQL 中，加权 RRF 在库内计算；**PowerContext**：读取偏好作为过滤条件与权重 |
| 核对 | `logs/06-recall-before.log`；`docs/evidence/hybrid-sql.txt`；执行计划见样例 3 |

## 样例 4：记忆改变了检索结果（核心样例）

| 项 | 内容 |
| --- | --- |
| 初始数据 | 在界面上把「记住我」清空（不选课程、不选来源类型、权重 0.6/0.4），保存；或直接用 `python verify.py` 自动准备 |
| 输入 | 同一个问题：`Raft 怎么保证不丢已提交的日志` |
| 操作 1 | 检索一次，记下命中列表 |
| 操作 2 | 右侧「记住我」只勾选课程 `分布式系统`、来源 `note` + `paper`，关键词权重拖到 0.7，点「保存到 PowerContext」 |
| 操作 3 | **同一个问题**再检索一次 |
| 预期 | 第二次的结果全部属于「分布式系统」且只含笔记/论文；首位从《组会纪要》变为《Raft 日志复制与提交规则》，Raft 原始论文进入结果。结果区上方「命中的检索参数（来自 PowerContext）」会显示新的过滤条件与权重 |
| 实测 | 第一次：`分布式系统 ×5 + 数据库系统 ×1`（redo/undo 笔记），首位《组会纪要：分布式课程设计分工》；第二次：`全部分布式系统`，首位《Raft 日志复制与提交规则》，第 6 位是 Raft 原始论文 |
| 技术参与 | **PowerContext**：偏好作为 `profile` 记忆持久化，下一次检索在生成 SQL 之前被读取；**seekdb**：新的过滤条件被下推到同一条 SQL 的 `WHERE` |
| 核对 | `logs/09-verify.log`；`docs/evidence/before-after.json`；`docs/screenshots/ui-recall-after-memory.png`；集成测试 `test_remembered_preference_changes_the_next_recall` |

命令行等价操作（需要 `pip install -e .`；否则用 `python verify.py`）：

```bash
# 先写一条宽范围的偏好
curl -X POST http://127.0.0.1:8788/api/profile -H "Content-Type: application/json" \
  -d '{"user":"demo-user","courses":[],"source_types":[],"keyword_weight":0.6,"vector_weight":0.4,"top_k":6,"tag":""}'
python -m syncrecall recall "Raft 怎么保证不丢已提交的日志"
# 再收窄
curl -X POST http://127.0.0.1:8788/api/profile -H "Content-Type: application/json" \
  -d '{"user":"demo-user","courses":["分布式系统"],"source_types":["note","paper"],"keyword_weight":0.7,"vector_weight":0.3,"top_k":6,"tag":""}'
python -m syncrecall recall "Raft 怎么保证不丢已提交的日志"
```

## 样例 5：答错 → 成为薄弱点 → 下一轮优先出现

| 项 | 内容 |
| --- | --- |
| 初始数据 | 无 |
| 操作 1 | 打开「复习队列」，任选一题点「忘了」 |
| 预期 1 | 弹窗显示下次复习时间（间隔 0 天）与「PowerContext 已记录薄弱点：<主题>」；「PowerContext 记住的薄弱点」一行更新 |
| 操作 2 | 点「刷新」，观察该主题的题目是否被标记「薄弱点优先」并靠前 |
| 技术参与 | **seekdb**：`review_card` 的 `ease/interval_days/repetitions/next_review_at` 被 SM-2 更新；**PowerContext**：`learning` 记忆里记录 `weak`，下一次排期读取它 |
| 核对 | `docs/evidence/event-log.json` 中 `grade_card` 行；集成测试 `test_review_grade_updates_schedule_and_memory` |
