# 一页技术说明

## 1. 一句话

SyncRecall 把课程笔记、论文、群聊、会议纪要放进 **seekdb**，用**一条 SQL** 同时做全文与向量检索并融合排序；
用 **PowerContext** 记住每个人「只看哪门课、偏好哪种来源、哪个观点还没想通」，让下一次检索从上次的终点接着开始，
并把读过的内容自动变成下一次要答的复习题。

## 2. 模块结构

```
                    ┌────────────────────── PowerContext 1.5.0 ──────────────────────┐
                    │ Scope(每用户) · kind: profile / focus / learning / session      │
                    └───────▲──────────────────────────────────────────────▲────────┘
            读取偏好/薄弱点 │                                              │ 写回会话交接/薄弱点
                            │                                              │
   web/ (原生 JS) ──► serve.py (FastAPI) ──► src/syncrecall/service.py ─────┘
                                                │
                                                │ 一条 SQL
                                                ▼
                    ┌────────────────────── seekdb 1.4.0 ───────────────────────────┐
                    │ note(ik 全文索引 ft_note + HNSW 向量索引 vidx_note + 结构化列) │
                    │ review_card(下次复习时间) · event_log(审计)                    │
                    └───────────────────────────────────────────────────────────────┘
```

| 文件 | 职责 |
| --- | --- |
| `store.py` | 建表 / 建索引、写入、`event_log` |
| `search.py` | 构造并执行那条混合检索 SQL（全文 + 向量 + 过滤 + 加权 RRF） |
| `memory.py` | PowerContext 客户端：读写四类记忆，处理「最新一条生效」 |
| `service.py` | 业务编排：`recall` / `review_plan` / `grade_card` / `seed` |
| `embedding.py` | 本地嵌入，sentence-transformers 优先，缺失时退化为确定性哈希 |
| `serve.py` | HTTP 接口 + 静态页面 |

## 3. 关键设计取舍

| 取舍 | 选择 | 原因 |
| --- | --- | --- |
| 双路检索在哪融合 | **库内**（`RANK()` + `w/(k+rank)`） | 应用层融合要把两路候选全拉回来，数据量一大就退化 |
| 记忆存哪 | **PowerContext**，不存 seekdb | 记忆是「关于人的状态」，与资料库生命周期不同；换 Agent 也能复用 |
| 如何判定「最新偏好」 | 读全部同 kind 记忆，按 Artifact `created_at` 取最后一条 | PowerContext 的 `memory/search` 按相关度返回，不是按时间；排序规则必须显式 |
| 嵌入放哪 | **本机**，不调云端 | 课题是个人学习资料，数据不出机；也免去评审配置 API Key |
| 没有模型时 | 哈希嵌入兜底 | 保证评审「装最少的东西也能跑通全流程」，且界面明确标注当前方式 |

## 4. 实测结果（不粉饰）

| 项 | 实测 |
| --- | --- |
| seekdb 版本 | `5.7.25-OceanBase seekdb-v1.4.0.0`（`oceanbase/seekdb:1.4.0`，`MODE=mini`） |
| 索引 | `ft_note` = FULLTEXT(`ik`)，`vidx_note` = VECTOR(HNSW) |
| 混合检索执行计划 | `VECTOR INDEX ADAPTIVE SCAN (PRE-FILTER)`，同算子内计算 `MATCH` 分数 |
| 单条 SQL 耗时（21 条笔记） | 29–60 ms |
| 一次 `recall` 端到端 | 120–280 ms（含 PowerContext 读写 + 本地嵌入） |
| 记忆生效前后 | 同一问题的命中范围从「分布式 + 数据库混排」变为「全部分布式系统，且 Raft 原论文入选」 |
| 测试 | `pytest tests -q` → 20 passed |

## 5. 已知不足

1. 语料只有 21 条，检索指标（Recall / nDCG）**没有统计意义**，本文不提供这类数字；
2. 默认嵌入是哈希回退，语义能力弱，真实效果需安装 `sentence-transformers` 后重新 `seed`；
3. Windows 上 PowerContext 只能用 SQLite 存储（嵌入式 seekdb 的 `pylibseekdb` 仅 Linux/macOS 发布），
   详见 `技术使用记录.md` 第 4 节；
4. 没有账号体系，`user` 只是 Scope 名。

## 6. 如果继续做

1. 引入真实用户（同学）试用 1–2 周，记录「整理一次复习资料从 X 分钟到 Y 分钟」；
2. 用 PowerContext 的 Handoff 能力替换当前手写的 `session` 记忆，把「上次停在哪」做成可审阅的交接记录；
3. 课程材料导入器（Markdown / PDF → 自动切题），减少 `seed.json` 这种手工造数。
