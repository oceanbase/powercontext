# v9 紧凑请求协议：离线比较结果

**v9 已通过本次冻结的离线门槛。** 三集共 1620 个原样本身份全部保留，候选成本合规后的事实覆盖及同请求完整可见覆盖均为 **495/495**；全部 arm 均没有新增事实、字面量或同请求可见性退化，也没有预算拒绝。

本阶段 provider 请求为零，新协议模型生成未运行。此结果允许进入独立线上预检准备，不能据此宣布真实模型生成、费用、生产接入或 issue 整体验收通过。未提交、未推送，原有 73 个暂存文件保持不变。

## 修改内容

新增独立 v9 包、合同、freeze/minimal/compare/summarize 离线入口和回归测试，不修改 v5/v6/v7/v8 代码或结果，不修改生产 API、依赖和 Atomic Memory 持久化。

- evidence 使用请求内 e 编号，输出还原为完整 evidence id，完整来源身份保留在内部绑定中。
- 字符串携带 q 编号；同一值有多个已支持区间时显式表示局部复制范围，无需重复发送独立 quote_index。复制仍要求正确引用、合法边界，不补齐遗漏。
- 完整投影保留原对象、数组、键名和类型化叶值；片段采用原字段路径字典及字节区间。原始 metadata、时间、归属和看似哈希的业务事实均保留。
- 只将已识别的程序来源信封内置化。未知信封字段、来源哈希冲突明确拒绝，避免隐藏事实。
- 请求绑定包含原输入、support、实际 payload、短编号、位置、指令和 schema。还原与渲染必须提供原绑定。
- 完整比较实际序列化/反序列化 wire payload，再读回选中值，核对输入、来源清单、复制映射和事实覆盖，避免只检查内部缓存。

事实选择不读取标签、不访问未准入 Source，不截断或规范化范围，不跨原请求合并。原请求编码后合规则保留边界；仍超限时才整段装箱。冻结的单次、累计和调用数门槛保持不变。

## 验收边界

本次只验证了冻结样例中的输入准备、协议还原、本地复制处理和字符估算预算。真实模型是否正确使用 copy、生成原子事实、保持精确字面量/Unicode，以及 provider 是否支持完整调用流程和审计链均未知。

生产 Memory 既有 NFC 与首尾 strip 不变，原始字节保真只证明到持久化之前。局部字符边界检查不等于完整 UAX 字素支持。没有生产接入或真实外部后端验收结论。
