# Pipeline 与评分合同离线评估

2026-10-28，本地完成 v10 实现、历史失败最小回放、三套合成数据的 1620 样本比较与完整行为回归。
候选 `bounded-fragments-v3` 的输入覆盖保持 495/495，但窗口对照有六个协议预算拒绝，
历史 v9 原子性失败仍存在；新协议的真实模型改善尚未测量。唯一总体决策为 `insufficient_evidence`。

## 实现与执行范围

- 新增评估专用 v10 模块。紧凑协议通过 extractor 进入真实 `AtomicMemoryGenerationPipeline.extract()`，
  不再用直接 SDK 调用替代这一验收边界。没有修改生产 Pipeline 或其他生产行为。
- 新指令通用地强调拆分可独立变化的断言，包括共享主体的断言，精确字面量和原始 Unicode 使用 copy。
  指令没有失败样本专属答案，不以事后拆句修复模型输出。
- 新评分将旧整句分数、原子事实覆盖和父事实语义覆盖分开。父事实必须全部子事实受支持且字面量齐全才能保留。
  审阅绑定 case、输入、支持范围和输出哈希，支持范围不得跨 materialization/projection 拼接。
- 五组共享新生成指令和 schema；原始事实选择、标签和门槛保持。窗口对照保留原 Source 窗口，
  不借用片段重装箱能力；片段 arm 只重装箱同一原请求内的完整已选范围。
- 更新逐项验收对照、运行合同、验证说明和中英文入口；脱敏机器结果进入 `results/v10-offline/`。

当前没有线上入口，没有新 provider 请求，没有生产 Memory 写入，未创建提交或推送。
工作区身份不满足运行前 Git 提交冻结。由于继承身份包含 Git revision，后续提交后必须重建并核对相关冻结产物。

原始集 900、validation-v2 360、validation-v3 360，共 1620 个样本；五组各 324 个，包含三档预算和三次重放。

### 窗口对照的六个拒绝

两个失败组合均在 4096 档，各重复三次：

- `many-source-overflow`；
- `validation-reordered-sources`。

v9 曾对控制请求执行协议片段拆包，增加请求数，因而不能把其结果完全视为原始 Source-count 控制。
v10 保留原窗口边界后，这六个样本的某个完整协议请求超出单次预算，整份计划标为不可执行；
原始选择的事实仍然存在，但成本合规覆盖减少 48 个事实计数。未发送任何部分计划。
完整投影和窗口控制原本分别还有 237、225 个准入预算拒绝；这些与新增协议拒绝分别计数。

因此不能声称所有 arm 均无退化或正式比较合同已完全闭环。后续需要明确：当新协议开销使窗口超预算时，
应如何在相同预算口径下执行真实 Source-count 缩窗、记录部分窗口和拒绝状态，并保持其与片段准入策略的区别。
修订该合同需要新的冻结身份，不能覆盖本次六个拒绝或用放宽预算、借用片段拆包来消除它们。

## 历史失败最小回放

读取 v9 首组已持久化输出，经真实 Pipeline 做本地原样回放；没有重新生成、拆分或改写候选。
这不证明历史真实 SDK 请求曾经过 Pipeline，也不是新 v10 模型输出。

| 口径 | 历史 v5 | 历史 v9 |
| --- | ---: | ---: |
| 必需原子事实 | 4/4 | 4/4 |
| 精确字面量 | 4/4 | 4/4 |
| 父事实语义覆盖 | 1/1 | 1/1 |
| 非原子候选 | 0 | 1 |
| 新合同离线诊断成功 | 是 | 否 |
| 旧整句 scorer | 0/1 | 0/1 |
| 旧合同 unresolved | 4 | 3 |

父事实语义覆盖解释了为什么旧整句 0/1 不能等同于语义全部丢失；它不覆盖旧评分或消除旧门槛失败。
v9 的复合候选仍然只计一个候选，仍判原子性失败。审阅继续标记 assistant，非独立人工审阅。
新评分始终输出 `formal_acceptance=false`，没有实现或替代正式联合生产 gate。
