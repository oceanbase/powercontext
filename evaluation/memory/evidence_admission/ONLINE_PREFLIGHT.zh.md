# v9 线上小样本预检准备

当前状态：v9 三集离线门槛通过，真实模型生成未运行。online-preflight-draft.json 是不可执行的请求清单，authorized_to_execute=false；当前没有 v9 线上适配器，provider 线路开销、usage 和金额上限尚未确定。

## 固定身份与预算

使用 v9-offline/code-freeze.json、三集 comparison/COMPLETE 和 summary.json 的身份，保留原始失败及 initial-flat-layout。小样本为同一原证据的 v5/v9 配对：4 个历史失败场景 × 3 预算 × 3 重放 × 2 协议，再加 3 个保护场景的 4K × 3 重放 × 2 协议，共 90 个样本身份。

本地请求草案为 v5 45 调用、v9 57 调用，共最多 102 次；输入字符估算分别 163677、180591，合计 344268；每调用最大输出 2048，合计最大输出 208896。实际 SDK 封装可能增加 token，以上不是实际 usage 或金额保证。

不得新增未计账的探测调用、失败重试、替换身份或挑选成功重放。若需要额外请求，应先记录新身份与预算，不得偷偷计入原冻结结果。

## 先补齐本地适配与审计

1. 新建独立评估会话及适配边界，保持冻结 v9 编码不变。实际发给模型的是 Request.payload 和 v9 指令、TemplateOutput schema；不能把 restore 后的原完整输入当作模型输入，否则压缩结论失效。原配置从已冻结 session.json 核对 provider/model/API base URL；本阶段不打开 shell 配置或提取密钥。
2. 用真实 SDK 的 MockTransport 捕获实际 HTTP 请求，核对模型参数、消息、schema、payload、短编号和指令与冻结草案一致，记录 SDK 添加的包装。v5 基线也按其原协议构造，不能加上 v9 的复制 schema。
3. 结构化输出解析后先通过 v9 的绑定、别名、copy 和来源校验，恢复完整 evidence id，再进入引用及事实评分。不能先用完整 evidence id 规则拒绝合法的 e0 别名，也不能因能复制而批准语义。
4. 复用已实现的私有尝试日志与 HTTP 响应捕获边界，验证每次尝试有唯一开始和终态；在 SDK 解析前保存受限私有响应、完整/截取哈希、长度、finish_reason、model 和 usage。不得记录凭据、认证头或向普通运维日志写内容。COMPLETE 不能替代这项证据。
5. 本地覆盖：传输/HTTP 失败、无效 JSON、截断或缺失 finish_reason、schema 错误、非法别名、跨来源复制、越界/Unicode 边界、语义或原子性评分不通过，以及取消。不同失败保留可审计分类，不能全部折叠成 invalid_output；缺失 usage 标为 unknown，不能计零费用。
6. 核对真实请求构造后的预算与审计完整性。上述验证通过后，再核对当前 provider 计价和可接受的金额上限；当前 currency_cost_cap=null，不能据此执行。

## 再决定是否开始真实小样本

只有本地适配、实际请求清单、失败审计和费用上限可审阅后，才决定是否执行真实请求。沿用既有 DEEPSEEK_API_KEY 变量配置，不打印或复制密钥。

开始时先运行冻结清单内的一组配对身份，其调用计入 102 次上限。若有请求格式、输出协议或终态审计问题，停止并保留该失败，不直接继续其余身份，也不通过重试替换。使用 concurrency=1、每调用至多一次请求。

评分同时保留旧合同分数、事实覆盖、原子性、精确字面量、原始字节保真、引用支持和输出合法性。独立子事实的语义审阅合同须在实际评分前冻结，并明确审阅者；不得看完新输出后修改旧标签或分母。不可完整容纳身份单独保留，不能算成完整成功。

小样本结束后报告真实 provider usage、未知用量、全部失败、实际与估算差异。通过仅允许考虑新协议的三集正式评测，不能恢复旧 v5 未运行任务并混合结果，也不能授权生产接入。旧 v5 失败证据继续保留。
