## 四、v14 协议设计

### 可引用单元（cell）

- 只处理已准入内容，不补入遗漏。
- 用确定性、与标注无关的规则构造单元：
  1. 反引号 `` `...` `` 包裹的 code span → 每个 span 一个单元（去除反引号，保留内部原字节）；
  2. 无 code span 的字符串叶 → 整叶作为一个单元（保证内联 emoji/组合字符/CRLF 可整体复制）。
- 每个单元绑定 Source、materialization、projection、字段、原始范围及协议版本。
- 请求内用短 ID（`c0 c1 …`），完整身份保存在内部绑定表，不进模型输入。
- 模型只引用单元 ID；还原器输出该单元对应原始字节。
- 未知 ID、其他请求的 ID、身份不匹配、非法组合明确拒绝；不自动纠正 ID、补全遗漏、规范化字面量或拆分复合候选。

### 输出 schema 变化

`CopySpan` 从 `{type, quote_id, byte_start, byte_end}` 改为 `{type, quote_id}`；还原时取整个单元值。`text` 部件不变（散文）。`evidence_ids` 仍引用完整顶层证据别名。

### 单元粒度离线验证

- 太粗 → 多个事实被逼成一个候选（原子性失败）。
- 太细 → 选择错误与协议开销上升。
- 不生成所有子串，不引入不可控存储/扫描/输入成本。
- CJK、emoji、组合字符、CRLF 必须满足承诺的原样还原规则。

### 编码与还原

复用 v9 的紧凑 wire 编码（`fields` 字典 + evidence 别名 + 内联单元），差异只在：内联的字符串不再是 `{v, q, copies}` 带局部字节切片，而是每个单元一个独立 `{c: id, v: 原字节}` 条目，模型只引用 `c`。还原时按单元 ID 取整段原字节，不解析任何字节偏移。
