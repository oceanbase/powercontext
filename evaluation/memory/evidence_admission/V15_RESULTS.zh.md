# v15 离线通过，最小线上清单预检失败

总体决策为 `insufficient_evidence`。三集离线比较通过；最小线上清单要求每例一次请求，Unicode 需要四次，
因此停止在 SDK 预检之前。本轮新增 provider 请求为 0，不修改生产行为，不推送。

## 实现

- 独立 `v15/` 协议，保留已有 v14 代码与结果；证据别名从全部准入证据构造，零单元与混合请求仍可引用。
- code span、Unicode 受保护序列和有界非 ASCII 字母片段可分别引用；不再把无反引号 Unicode 整叶作为单元。
  原始无反引号样例、组合字符、ZWJ、修饰符、旗帜、变体选择符及 CRLF 均有针对性回归。
- 单元内容内联进证据字符串，不再另建重复正文表。JSON 原类型、定界符和完整字段内容可逐字节往返还原。
- 完整请求绑定证据、别名、支持范围、schema、指令与单元；调用边界在生成前后核验，拒绝篡改。
- 保留通用独立断言拆分说明与无关示例；允许一个事实使用多个 copy，不自动拆分模型的复合输出。
- 离线汇总验证三集同一身份、样本集合完整唯一、范围选择不变、wire 还原、覆盖与三次重放确定性。

## 停止原因

| 冻结最小清单，均为 4K | 计划请求数 | 单次估算输入 token | 单元总数 | 一次请求门槛 |
| --- | ---: | --- | ---: | --- |
| exact-literals | 1 | 3795 | 4 | 通过 |
| unicode-boundaries | **4** | 3864、3939、3940、2215 | **1195** | **失败** |

Unicode 原始未装箱请求估算 10170。虽然不重复正文，有界 Unicode 单元仍把大量非必要填充编码成引用单元，
单元包装开销过高。四次装箱后的累计估算为 13958，各次低于 4096，累计低于 32768，
因此普通离线预算门槛确实通过；失败的是冻结最小线上清单的每例一次请求约束，两者不能混为一谈。

没有扩大清单到四次、只发送计划前缀、改变单元参数或重试模型。整组最小清单未进入 SDK 预检、凭据读取或真实发送。
程序能复制目标字节，不代表模型会选对单元；本轮没有 v15 模型质量结果，也没有正式联合比较或生产后续授权。
