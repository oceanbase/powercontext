# v11 离线结果与验收差异

总体决策为 `insufficient_evidence`。窗口对照的完整协议预算缺口已在离线比较中修复，
没有新 provider 请求，正式线上生成和 issue 联合验收未完成。生产行为未修改。

## 实现与范围

[v11 合同](V11_PROTOCOL.zh.md)让真实 Source 窗口同时满足冻结原生选择预算和完整 v10 协议预算。
超预算时通过真实持久化缩减提示将 Source 数减半，再从同一消费位置重读；不截断字段、拆分 Source 或改变候选选择。
单 Source 下限或资源上限拒绝保留已准入的前缀，明确记录遗漏和完整样本状态。
本地取消、Scope 隔离、恢复提示和真实 Pipeline 的前缀提取均经过回归。

历史内容身份与执行提交身份分开：历史结果原始哈希固定，源码、运行时、数据、协议和配置仍须相同。
本次执行单独记录 HEAD，未认证提交冻结；模拟提交元数据测试不能替代实际提交。

比较覆盖三套冻结数据、五个 arm、三个预算和三次重放，共 1620 个样本身份。
其中重新执行 324 个窗口样本：279 个运行新预算计划，45 个故障/取消样本重跑既有边界。
其他 1296 个样本按哈希和身份校验后逐字段原样复用，不能称为本次重新执行全部样本。

六个恢复样本为 `many-source-overflow` 和 `validation-reordered-sources`，均为 4096 预算、三次重放。
每个恢复样本保留 8 个必需事实计数。这里的 48 是跨重放计数，不是 48 条独立事实。

v9 与 v11 协议不同，不能据此归因模型效果。v10 有协议拒绝，其原始计划数不能作为完整可执行成本基线。
候选 v3 的复用值为 411 次潜在调用、1,320,978 个估算输入 token，未发生策略或成本重算。

## 历史失败与下一步

[v10 的六个预算拒绝](V10_RESULTS.zh.md)保持原样，不覆盖为通过。
v9 首组真实复合候选的原子性失败、旧整句 scorer 0/1 的 unresolved 状态也保持原判。
v11 只修复窗口输入计划，没有新的模型输出，不能证明事实拆分、copy、Unicode 或引用质量已经改善。

下一轮应先提交冻结新合同及依赖，再按新执行身份完成离线核验、真实 SDK 请求与费用预检，
然后经实际 `AtomicMemoryGenerationPipeline.extract()` 验证原子性、精确字面量、Unicode、copy 和支持范围。
通过小样本审计后再决定是否扩展正式联合矩阵。失败原样保留，不直接续跑尚未运行的两个数据集。
最终仍需统一生成评分合同、覆盖全部应执行 arm，并完成关键语义审阅与脱敏交付。
所有远端 provider、OceanBase、真实宿主、进程恢复能力仍超出此次本地证据范围。

完整评估回归 371 项通过（1592 条既有类别警告），新增回归 16 项通过。
本评估模块、根项目类型检查、两套锁文件检查、全量与新增文件 hooks、wheel/sdist 内容核验均通过。
Ruff 0.16.0 的全评估检查仍有 13 项保留文件诊断，整个 evaluation 类型检查仍有一项 LongMemEval 既有错误；
新增 v11 代码和测试无 Ruff 诊断。未重跑其他 Python 版本。

具体检查和既有诊断见 [VALIDATION.md](VALIDATION.md)，逐项 issue 状态见 [验收对照](ACCEPTANCE.zh.md)。
