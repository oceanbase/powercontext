# Production native lexical analyzer: validation and measurements

Measured on 2026-11-21. This report covers the normal installed PowerContext entry point, `powercontext.builtin.artifacts.search.analyze_text(str) -> str`.

## Production integration

The search module directly imports `powercontext._lexical.analyze_text`. The old Python projection wrapper has been removed. Normal wheel and editable installations build/include the native module; callers need no pytest plugin, backend switch or fallback. Python span/query helpers remain because they implement offsets and query admission, separate from this projection-only migration unit. This PR replaces this unit, not the whole Python service.

The owning source is `src/powercontext/builtin/artifacts/lexical/`. Evaluation inputs and reports remain under `evaluation/performance/lexical/`. Rust is pinned to 1.95.0, matching the gateway. Windows uses MSVC. The root package keeps Hatchling/Hatch-VCS and includes the internally built maturin extension in its own wheel; no separate lexical package is required at runtime.

`TEXT_ANALYZER_VERSION` remains `jieba-0.42.1-words-v1`. Projection contents, schema, query admission and the public callable signature are preserved. Existing persisted projections require no migration for this replacement.

## Installation and compatibility boundary

The root wheel is platform specific, tagged `cp311-abi3`, and carries `powercontext/_lexical.pyd` on Windows. Its metadata has `Root-Is-Purelib: false`. Runtime wheels exclude Rust sources and Unicode build tables. Source distributions include the build hook, Cargo manifest/lock, Rust source and Unicode tables.

Supported Python versions are explicitly **3.11 through 3.14** (`>=3.11,<3.15`), tightened from the previous `<4.0` metadata. Each runtime uses the corresponding Unicode 14.0, 15.0, 15.1 or 16.0 tables, exported from that CPython runtime. Unicode normalization preserves the behavior of characters unassigned in older versions. Future Python versions need corresponding tables and verification before this bound is extended.

Installing a compatible binary wheel needs no Rust compiler. Source installation, editable development and source-based container builds require Rust 1.95.0 and a platform C toolchain. Native CI builds actual manylinux_2_28 wheels for x86_64/aarch64, macOS wheels for x86_64/arm64, and Windows x86_64 wheels. These jobs install-test the abi3 wheel on CPython 3.11–3.14. Release publication waits for the platform builds and retains the existing candidate-wheel/sdist acceptance gate. **The GitHub platform matrix and Docker execution were not completed locally.**

## Installed default-function equivalence

The same root Windows wheel was installed into four separate environments. Validation used each environment's own interpreter with `-I`; no checkout path injection or experimental analyzer activation was used. Native function identity and seven non-string `TypeError` cases were checked on each interpreter.

| --- | --- | ---: | ---: |
| 3.11.15 | 14.0 | 12,548 | 0 |
| 3.12.13 | 15.0 | 12,610 | 0 |

The committed verifier covers frozen corpus records, all casefold/decomposition characters, word-range edges, surrogate strings, seeded mixed strings and public documents. The oracle is the retained Python span implementation using the running interpreter's Unicode semantics and Jieba 0.42.1.

An independent reviewer additionally compared every single Unicode codepoint, including unassigned codepoints, noncharacters and surrogates; the prior strict corpus; combining/casefold inputs; and 30,000 seeded mixed strings per interpreter. Boundary validation additionally exhausts all 71,178 characters inside the PowerContext Han ranges but outside Python Jieba's U+4E00–U+9FD5 scoring range, with repeated words on both sides. It independently compared every table with a full scan of the corresponding CPython runtime. Its oracle was AST-extracted retained Python code with the real stdlib/Jieba, not expected values generated by Rust.

| CPython | Independent comparisons | Mismatches |
| --- | ---: | ---: |
| 3.11 | 1,231,092 | 0 |
| 3.12 | 1,231,132 | 0 |
| 3.13 | 1,231,132 | 0 |

Counts describe comparisons, not a proof over all possible Unicode strings. The independent probe directly loaded the native artifact; the separate installed-wheel verifier establishes the actual default entry point. Raw summaries are in [production-validation.json](production-validation.json).

The `丁丁丁㐀` review reproduction exposed a scoring-boundary defect: Rust originally included the extension character in the same DAG, changing a floating-point tie and word order. Native scoring now uses Python Jieba's U+4E00–U+9FD5 boundaries and emits other Han characters individually. Seven public-interface regression cases were run against the faulty build first (six failed, one passed), then all seven passed after the fix. The counts above and binary hash below refer to the corrected build.

## Packaging and persisted search

The final source distribution was rebuilt through `run_upgrade_release_gate.validate_sdist()`. All **813 wheel members excluding RECORD** matched the direct root wheel byte for byte. The wheel has 814 ZIP members in total. The native binary SHA-256 is:

```text
b4600b0d8d0db72d73d79d65a64e1048aab4a4c7920802bc90c15f8d4b475cd4
```

This hash identifies the Windows release binary used for the reported installed-default checks and timings. Source distributions were also rebuilt from the final build-hook/cache configuration. A deeply nested Windows rebuild path exceeded the local linker path limit; rerunning the unchanged gate in a short temporary directory passed.

A separate clean core-only wheel installation passed the core export smoke test and native English/Chinese projection checks with neither `httpx` nor Python `jieba` installed.

Real installed-wheel builtin smoke tests created SQLite memories, closed and reopened the runtime, read back the exact reference/content and searched the persisted record. CPython **3.11 and 3.14 passed**. The corresponding 3.12/3.13 runs were blocked before database work by Windows stdlib `asyncio` socketpair initialization. A minimal `asyncio.run(asyncio.sleep(0))` with no PowerContext import reproduced the stall in `_fallback_socketpair`/`socket.accept`. Those two persistence runs are **unverified**, despite their analyzer-equivalence checks passing.

## Focused tests and static checks

The focused pytest run completed with **447 passed, 44 skipped** (85.02 seconds wall time). It covers the 36 native interface tests, query/admission/chunking behavior, Atomic/Topic Memory search, persistence scoring, lexical end-to-end tests, upgrade projections, CI/release gates, Docker contracts and installation orchestration.

The 44 skips comprise 13 real seekDB migration cases, 13 real OceanBase migration cases, 6 Linux subreaper cases, 5 macOS executable cases, 4 Ubuntu uv probes, 2 GNU timeout/POSIX signal cases and 1 POSIX venv symlink case. No real seekDB/OceanBase acceptance claim follows from this run.

On Windows this run used `PYTHONUTF8=1` and propagated the test control variables `SCOPE_RESULT`, `UPGRADE_SELECTED` and `UPGRADE_RESULT` through `WSLENV`, because subprocess `bash` resolves to the WSL launcher. Without that propagation two shell control tests fail before exercising their intended controls.

Rust 1.95.0 MSVC formatting, clippy with `-D warnings`, and four Rust tests passed. The same four Rust tests passed under WSL/Linux Rust 1.95.0 using the platform-neutral Cargo cache offline. Changed-file Ruff/type checks and workflow action-pin validation passed. Content/format hooks passed. Whole-repository `ty` still reports **93 existing Windows/platform diagnostics**; `make check` is not reported as passing.

## Production analyzer performance

Environment: Intel Core Ultra 5 225H, Windows x86_64, CPython 3.14.3, Rust 1.95.0 release, one thread. The retained Python projection is compared with the installed public default native function. Equality is checked before timing. Nine warm rounds alternate execution order and include the call boundary, conversion and output allocation. Document reading is outside timing. Full samples are retained in [production-benchmark.json](production-benchmark.json).

| Workload | Inputs / characters | Python median (ms) | Rust median (ms) | Speedup |
| --- | --- | ---: | ---: | ---: |
| Chinese public documents | 12 / 101,280 | 115.9114 | 9.7368 | **11.90×** |
| English public documents | 12 / 140,040 | 11.3287 | 3.4048 | **3.33×** |
| Short query repeated | 1,000 / 26,000 | 11.0113 | 1.3363 | **8.24×** |

These are warm analyzer measurements. CPU frequency, affinity and background system activity were uncontrolled; individual samples vary. They establish neither cold-start performance nor HTTP, external-backend, host or complete Server acceleration. The Chinese character count reflects the current installation documentation, so it differs from the historical experiment. Historical pilot measurements are separate evidence.

## Reproduction

Use Rust 1.95.0 and a platform C toolchain for source builds:

```text
uv sync --frozen
cargo fmt --manifest-path src/powercontext/builtin/artifacts/lexical/Cargo.toml --all --check
cargo clippy --locked --manifest-path src/powercontext/builtin/artifacts/lexical/Cargo.toml --all-targets -- -D warnings
cargo test --locked --manifest-path src/powercontext/builtin/artifacts/lexical/Cargo.toml
uv build --out-dir output/lexical-production/dist
```

Install that root wheel with the `builtin` extra in a clean Python 3.11, 3.12, 3.13 or 3.14 environment. With its interpreter:

```text
python -I scripts/ci_verify_native_wheel.py
python -I evaluation/performance/lexical/scripts/verify.py --output output/lexical-production/validation.json
python -I scripts/ci_role_smoke.py builtin
python -I evaluation/performance/lexical/scripts/benchmark.py --output output/lexical-production/benchmark.json
```

Run the focused behavior and delivery tests:

```text
uv run --no-sync pytest -q tests/builtin/artifacts/test_native_lexical.py tests/builtin/artifacts/test_text_search_admission.py tests/builtin/artifacts/test_lexical_search_requests.py tests/builtin/artifacts/topic_memory/test_chunking.py tests/builtin/artifacts/atomic_memory/test_search.py tests/builtin/artifacts/topic_memory/test_search.py tests/builtin/persistence/test_atomic_memory_search_scoring.py tests/e2e/test_unified_lexical_search.py tests/e2e/test_lexical_admission.py tests/e2e/test_lexical_projection_upgrade.py tests/test_ci_pipeline.py tests/test_docker_contract.py tests/test_upgrade_release_gate.py tests/test_upgrade_publication.py tests/test_ci_installation_roles.py tests/test_ci_release_verification.py
```
