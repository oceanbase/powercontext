# 代码与测试

本文记录本次任务的代码修改、测试设计、实际运行结果，以及"没有验证到的部分"。

## 1. 修改前后

| 阶段 | 代码 | 依据 |
| --- | --- | --- |
| 修改前 | seekdb 提交 `108fe22`（未改动） | `agent/snapshots/sql_parser_mysql_mode.before.y` |
| 修改后 | 同一提交 + MiniMax 补丁 | `agent/snapshots/sql_parser_mysql_mode.after.y` |

修改只涉及一个文件 `src/sql/parser/sql_parser_mysql_mode.y`（+6 行），完整差异见
`agent/code/minimax-change.diff`：

```diff
@@ -3172,6 +3172,12 @@ MOD '(' expr ',' expr ')'
   malloc_non_terminal_node($$, result->malloc_pool_, T_FUN_SYS_ARRAY, 1, $2);
 }
+| column_ref '[' expr ']'
+{
+  /* col[i] reads or assigns one element of an ARRAY column */
+  malloc_non_terminal_node($$, result->malloc_pool_, T_OP_ARRAY_INDEX, 2, $1, $3);
+  $$->flag_ = 0;
+}
  | vector_distance_expr
```

### 这个改动做了什么、没做什么

* 做了：让文法认识 `<column-ref> '[' expr ']'`，并建立独立节点 `T_OP_ARRAY_INDEX`，
  不再把 `col[i]` 当成"列名 + 数组字面量"。这正是 ARR-005 要求的解析层前提。
* 没做：节点类型定义、解析（resolver）路径、执行期表达式、INSERT/UPDATE 目标列部分写入、
  回归结果文件。因此 **功能尚未完成**，见第 4 节"未验证"。这是如实记录的中间状态，
  不是被打包的完成品：guard 在 after 阶段报告 `acceptance 1/5 pass`，没有把半成品当通过。

### 变更是否安全

`column_ref '[' expr ']'` 只有在"一个标识符后面紧跟 `[`"时才会被归约；现有语料里的
`[1,2]`、`array(1,2)`、`[[..],[..]]` 前面没有标识符，仍走原有 `'[' expr_list ']'` 产生式，
因此 ARR-006/ARR-007 的行为不受影响（兼容检查在应用补丁前后都是 pass）。

## 2. 新增测试

### 2.1 验收/兼容用例（真实 seekdb 服务）

定义在 `tests/suite.json`（由 `context/scenarios.py` 生成），共 7 个用例 40 条 SQL：

| --- | --- | --- | --- |
| TC-INSERT-01 | 验收 | ARR-001 | 元素级 INSERT 成功，只写入目标元素，其余为列默认值 |
| TC-UPDATE-01 | 验收 | ARR-002 | 只改写目标元素，其他元素保持 |
| TC-DELETE-01 | 验收 | ARR-003 | 元素谓词命中正确行 |
| TC-READ-01 | 验收 | ARR-004 | 1-based 读取；越界返回 NULL |
| TC-PARSER-01 | 验收 | ARR-005 | 文法产生独立元素访问节点 |
| TC-COMPAT-01 | 兼容 | ARR-006 | 错误码 7602/5083 与 reverse 输出不变 |
| TC-COMPAT-02 | 兼容 | ARR-007 | 现有 ARRAY DDL/DML 形状不变 |

基准观测（修改前）记录在 `tests/golden_baseline.json`：每条 SQL 的成功/错误码、返回行和摘要，
由 `scripts/record_baseline.py` 在未修改的树上生成。guard 用逐条比对（错误码而非报错文本），
避免无关文案差异造成误判。

## 4. 未验证 / 已知缺陷（如实记录）

| 项 | 状态 | 原因 |
| --- | --- | --- |
| C++ 编译 | **未编译** | 本机无 bazel/g++；seekdb 全量构建在 16 GB / 10 核的机器上不可行 |
| `T_OP_ARRAY_INDEX` 节点定义 | **缺失** | 补丁只加语法；节点类型、解析路径、执行期实现都要在完整构建下迭代 |
| INSERT/UPDATE/DELETE/SELECT 的服务层验收 | **失败** | 依赖带补丁的构建 |
| 回归 `.result` 重录 | **未做** | `vector_index/array` 套件需 mysqltest + 构建产物，本机没有 |
| `grammar_check/array_index_probe.cpp` | **未编译** | 需与构建一致的 `libobparser` 头文件与链接参数；默认使用 `static_check.py` |

这两层检查的定位是：`static_check` 证明"文法确实少了产生式、补丁确实补上了"，
`guard` 证明"同一组 SQL 在修改前失败、修改后应通过"，并守住兼容行为。
它们不能替代真实构建，因此上诉表格中的"未编译"必须随作品一起告知评审。
