# 验证样例

任务：seekdb 的 ARRAY 列支持按元素访问（`col[i]`）。
被测服务：`OceanBase seekdb 1.4.0.0`（镜像 `oceanbase/seekdb:1.4.0-100000172026082615`），
`127.0.0.1:2883`，账号 `minimax_test`，库 `minimax_scenario`（每次运行前重建，保证初始数据一致）。

检查分两层：

* **parser_only** —— 语法层：`grammar_check/static_check.py` 直接读 seekdb 文法源，判断是否存在
  `column_ref '[' expr ']'` 产生式及其建立的节点；存在即 PASS。
* **live_server** —— 真实服务层：`context/harness.py` 把样例中的 SQL 发到运行中的 seekdb，逐条记录
  成功/错误码与返回行，再与 `tests/golden_baseline.json`（修改前记录的基准观测）比对。

下表的 "修改前" 是基准观测的原样结果；"修改后期望" 是规格陈述要求的结果，由 `context/guard.py`
的 `AFTER_EXPECTATIONS` / `AFTER_ROWS` 编码，guard 会逐条比对。

## 1. 样例清单

| 编号 | 类型 | 规格 | 说明 |
| --- | --- | --- | --- |
| TC-INSERT-01 | 验收 | ARR-001 | 元素级 INSERT 目标 |
| TC-UPDATE-01 | 验收 | ARR-002 | 元素级 UPDATE 目标 |
| TC-DELETE-01 | 验收 | ARR-003 | 元素谓词 DELETE |
| TC-READ-01 | 验收 | ARR-004 | 元素读取（表列与字面量） |
| TC-PARSER-01 | 验收 | ARR-005 | 文法产生独立元素访问节点 |
| TC-COMPAT-01 | 兼容 | ARR-006 | 既有数组运算/函数错误码与 reverse 行为 |
| TC-COMPAT-02 | 兼容 | ARR-007 | 既有 ARRAY DDL/DML 形状 |

## 2. 初始数据

每个样例运行前重建 `minimax_scenario` 库，样例自带建表与初始数据：

```sql
create table tc_insert(id int not null primary key, slots array(int) not null, note varchar(32));
insert into tc_insert values (1, [0, 0, 0, 0], 'widen');
```

其余样例同样在 `tests/suite.json` 中写明，见第 4 节完整列表。

### TC-INSERT-01（ARR-001）

| # | SQL | 修改前 | 修改后期望 |
| --- | --- | --- | --- |
| 1 | `drop table if exists tc_insert` | ok | ok |

## 4. 运行方式

```bash
cd minimax
export SEEKDB_REPO=/path/to/seekdb
export PYTHONIOENCODING=utf-8

python scripts/init_db.py            # 只为保证库与账号存在
python scripts/record_baseline.py    # 记录基准观测（修改前执行一次）
python run.py guard --stage baseline # 期望：全部 pass（= 与基准完全一致）
python run.py guard --stage after    # 修改前执行：期望 5 个验收项 fail、2 个兼容项 pass
python run.py guard --stage after    # 修改后执行：期望 7 个检查全部 pass
```

## 5. 结果对照（本次提交的实测记录）

修改前（未打补丁的 seekdb 1.4.0 服务 + 未修改的文法源），`python run.py guard --stage after`：

```
[FAIL] TC-INSERT-01   #3 expected success, got error 1064 ...
[FAIL] TC-UPDATE-01   #3 expected success, got error 1064 ... #5 expected success, got error 1064 ...
[FAIL] TC-DELETE-01   #3 expected success, got error 1064 ...
[FAIL] TC-READ-01     #0/#1/#5/#6 expected success, got error 1064 ...
[pass] TC-COMPAT-01   matches the unmodified tree
[pass] TC-COMPAT-02   matches the unmodified tree
[fail] grammar-check  element-access node: none
acceptance 0/5 pass, compatibility 2/2 pass
```

同一命令在语法层指向打了 MiniMax 补丁的检出（`SEEKDB_REPO=<打过补丁的 seekdb>`）时：

```
[pass] grammar-check  element-access node: T_OP_ARRAY_INDEX
```

即：语法层先变绿，服务层要等一个带该补丁的 seekdb 构建。完整日志见 `logs/`。

## 6. 重量方法（重新记录基准观测）

换了 seekdb 版本或镜像后，基准观测需要重录（否则 oracle 只代表旧版本）：

```bash
python scripts/record_baseline.py --server-user minimax_test --server-password minimax_test_dev
git add tests/golden_baseline.json      # 重录会产生 diff，评审可据此判断是否换了基线
python -m pytest tests -q               # 上下文模块自测
```
