# Gateway 追问消歧评测

在登录超时的“继续”场景中，开启消歧后 **3/3 次**把此前约定的“保留原异常类型”传给了主模型，关闭时 **0/3 次**。真实 DeepSeek Chat 还验证了上一轮主请求可为下一轮消歧预热前缀。

## 怎么测

- **功能开关对照。** DeepSeek Flash Chat、隔离 SQLite Core、6 条预置记忆。使用 24 条标注样本，涵盖模糊追问、明确任务、切换任务和工具续写，每类 6 条。开启和关闭各跑 72 次，同例三次。检查实际 Core 查询、主模型收到的记忆和 provider usage。[样本](../../../gateway/crates/pc-gateway-app/tests/fixtures/context_disambiguation.json) · [逐次结果](results.json)
- **JSON 模式对照。** 固定同一份两步指令，24 条样本各跑两次。两组的唯一区别是 Chat 辅助请求是否设置 JSON 模式。跨轮实验使用保留两步指令和 JSON 模式的本地提交 `97ab095e9`。[评测入口](evaluate.py) · [逐次结果](follow-up-results.json)
- **跨轮前缀验证。** 对三组各用一个新的带长前缀会话，先发一次普通主模型请求，再把真实回复和追问追加到原消息。核对上游载荷的共有消息完全一致。对照组使用同长度但此前从未发送的前缀。读取实际消歧调用返回的缓存 token。[前缀验证数据](follow-up-results.json)

## 测到了什么

| 功能开关对照 | 关闭 | 开启 |
| --- | --- | --- |
| 应召回时只注入目标记忆 | 21/36（58.3%） | 31/36（86.1%） |
| 无需召回且零准备、零注入 | 18/36（50.0%） | 32/36（88.9%） |
| 两项合计，主模型收到的上下文符合标注 | 39/72（54.2%） | 63/72（87.5%） |
| 单次请求 P95 | 1.19 秒 | 2.44 秒 |
| 72 次请求的估算费用 | $0.00804 | $0.01107（+37.6%） |

同一提示词开启 JSON 模式后，合规输出从 **31/36 到 34/36**，目标记忆命中从 **19/24 到 23/24**。这项对照使用了两步候选指令，功能开关的费用和时延来自初次开关实验。

**跨轮缓存实测。** 三次有上一轮主请求的消歧调用各命中 **1,536 个缓存 token**，约占输入的 **83%**。三次未预热的对照均为 **0**。这验证了当前方案在 DeepSeek Chat、长前缀保持一致时能命中。实际命中仍取决于上游、可复用前缀长度和缓存状态。

**任务收益仍需验证。** 现在测到的是主模型更常拿到正确约束。任务最终成功率、用户纠正轮次和每完成一个任务的总费用还需要多轮任务 A/B。按本次开关对照的平均请求费用粗算，在成功率和请求构成可比时，主请求次数减少约 **27%** 可达到费用持平。
