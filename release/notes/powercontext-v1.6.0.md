# PowerContext v1.6.0

## English

PowerContext v1.6.0 introduces knowledge bases and the stable Gateway. Import existing documents into searchable, revisioned knowledge bases, and reuse the Agent conversation's cached prefix to reduce uncached input for memory extraction. Plugin hot reload, Source collection and clearer processing diagnostics complete the release.

- Introduce the knowledge-base plugin: organize spaces and knowledge bases, upload Markdown and PNG/JPEG/WebP images or import from allowed Server directories, and use OCR, revisioned chunks and hybrid retrieval. Inspect processing, test retrieval, edit chunks, forget documents and reprocess them in the Dashboard. Exact document revisions retain their evidence and historical chunks. SQLite, seekDB and OceanBase are supported; install the optional knowledge-base dependencies and plugin explicitly. PDF/Office ingestion and generated answers are outside this release. ([#2658](https://github.com/oceanbase/powercontext/pull/2658), [#2715](https://github.com/oceanbase/powercontext/pull/2715))

- Release the stable Gateway with optional cache-aware Atomic Memory extraction for Responses conversations. Append extraction instructions to the exact Agent request and final response, preserving the provider-cache prefix. Core uses this path only when its estimate is cheaper than normal extraction; otherwise it falls back. Enable capture and prefix extraction on the Gateway and configure the Server extraction URL. The feature is off by default. Codex subscriptions support it only with a confirmed non-enforcing Core and use the same subscription account; other subscriptions use normal extraction. Cache hits reduce billed uncached input, not necessarily total input tokens. Cache misses and fallback calls can add cost, and no fixed saving percentage is promised. ([#2435](https://github.com/oceanbase/powercontext/pull/2435), [#2776](https://github.com/oceanbase/powercontext/pull/2776), [#2717](https://github.com/oceanbase/powercontext/pull/2717))

- Add opt-in one_pass Atomic Memory processing and allow its multi-step conversation to run after the cached Agent prefix. It keeps extraction, related-memory reconciliation and re-checks in one conversation, with Core validation before publication. The prefixed path also sends compared existing memories to the Agent model/account. Quality and total cost depend on the workload, model and cache behavior; the default processing mode is unchanged. ([#2729](https://github.com/oceanbase/powercontext/pull/2729), [#2775](https://github.com/oceanbase/powercontext/pull/2775))

- Hot-reload directory plugins from validated snapshots, run plugin-owned data upgrades before activation, and expose declared plugin routes through OpenAPI and MCP. Collect Sources with Server and device runners using centrally managed targets. Plugins own their data and upgrade logic; back up plugin databases and local snapshots together with Core storage. ([#2638](https://github.com/oceanbase/powercontext/pull/2638), [#2639](https://github.com/oceanbase/powercontext/pull/2639))

- Expand provider-specific OAuth subscription adapters and add a Deep Agents integration. Improve DSH companion-memory support, long-prompt recall, credential forwarding and shared prompt-privacy handling across integrations. Subscription routes retain their documented protocol and protection limits; provider/account usage rules still apply. ([#2562](https://github.com/oceanbase/powercontext/pull/2562), [#2684](https://github.com/oceanbase/powercontext/pull/2684), [#2656](https://github.com/oceanbase/powercontext/pull/2656), [#2647](https://github.com/oceanbase/powercontext/pull/2647), [#2669](https://github.com/oceanbase/powercontext/pull/2669), [#2712](https://github.com/oceanbase/powercontext/pull/2712))

- Make processing failures and recall decisions easier to inspect in the Dashboard, including publication, model-usage accounting and provider failures. Retain same-execution prepare diagnostics separately from Sources and public body-free Receipts. These private diagnostics can contain queries and candidate/final text and have no automatic expiry. Expose Experience recurrence effectiveness as a read-only projection. ([#2664](https://github.com/oceanbase/powercontext/pull/2664), [#2681](https://github.com/oceanbase/powercontext/pull/2681), [#2676](https://github.com/oceanbase/powercontext/pull/2676), [#2708](https://github.com/oceanbase/powercontext/pull/2708), [#2598](https://github.com/oceanbase/powercontext/pull/2598), [#2688](https://github.com/oceanbase/powercontext/pull/2688))

- Improve long-candidate recall of short related memories, wait for Source configuration locks, allow Source capture during Experience incubation, drain pending usage writes more reliably, and preserve distinct terminal Gateway turns. ([#2628](https://github.com/oceanbase/powercontext/pull/2628), [#2691](https://github.com/oceanbase/powercontext/pull/2691), [#2693](https://github.com/oceanbase/powercontext/pull/2693), [#2706](https://github.com/oceanbase/powercontext/pull/2706), [#2717](https://github.com/oceanbase/powercontext/pull/2717))

- Upgrade Server, Gateway, SDK, CLI and integrations together. Freeze the cumulative migration as v1_6_0 after the preserved v1_5_2_pr2639 revision; the 1.6.0 schema head is v1_6_0. This adds the private prepare-diagnostics store without backfilling historical queries. Existing managed databases require explicit maintenance. Databases with retained legacy plugin registrations/data still have no supported in-place upgrade path; uninstalling a plugin does not remove those records. Database upgrade support is limited to source-version, target-artifact, backend and configuration combinations that pass full Server acceptance. ([#2713](https://github.com/oceanbase/powercontext/pull/2713), [#2639](https://github.com/oceanbase/powercontext/pull/2639), [#2664](https://github.com/oceanbase/powercontext/pull/2664))

### Installation and compatibility

```bash
uv tool install --force "powercontext[cli,server]==1.6.0"
```

Use `powercontext-v1.6.0` for integration refs and reopen Agent sessions. The Gateway remains optional; its stable release does not enable prefix extraction automatically. Follow the knowledge-base guide to install the plugin and optional dependencies. The upgrade gate retains all twelve registered 1.3.0 source/backend/configuration profiles; the separately registered 1.4.0 path is not certified by that gate. Unpublished `000` databases and recovery plans are disposable: rebuild them instead of stamping them as released.

Guides: [Knowledge bases](https://github.com/oceanbase/powercontext/blob/powercontext-v1.6.0/docs/en/docs/workflows/knowledge-base.md) · [Gateway deployment](https://github.com/oceanbase/powercontext/blob/powercontext-v1.6.0/docs/en/docs/operate/deploy-server.md) · [Database migrations](https://github.com/oceanbase/powercontext/blob/powercontext-v1.6.0/docs/en/docs/operate/database-migrations.md)

## 中文

PowerContext v1.6.0 首次发布知识库，并推出 Gateway 正式版。将已有文档导入可检索、可追溯版本的知识库；复用 Agent 对话的缓存前缀，减少记忆提取时重复支付的非缓存输入。本次还带来插件热重载、Source 采集和更清晰的处理诊断。

- 首次发布知识库插件：按空间和知识库组织资料，上传 Markdown、PNG/JPEG/WebP 图片，或从允许的 Server 目录导入，通过 OCR、版本化分块和混合检索查找内容。在 Dashboard 中查看处理状态、测试召回、编辑分块、遗忘文档和重新处理，精确文档版本保留证据与历史分块。支持 SQLite、seekDB 和 OceanBase；需要显式安装知识库可选依赖和插件。本次不包含 PDF/Office 导入和答案生成。 ([#2658](https://github.com/oceanbase/powercontext/pull/2658), [#2715](https://github.com/oceanbase/powercontext/pull/2715))

- 发布 Gateway 正式版，为 Responses 对话提供可选的缓存感知 Atomic Memory 提取。在 Agent 的精确请求和最终响应后追加提取指令，保留供应商可复用的缓存前缀。Core 仅在估算比常规提取更便宜时采用此路径，否则回退。需要在 Gateway 开启采集和前缀提取，并配置 Server 的提取地址；默认关闭。Codex 订阅仅在确认 Core 未强制执行保护时支持此路径，使用同一订阅账户；其他订阅仍走常规提取。缓存命中减少按非缓存价格计费的输入，不一定减少输入 token 总量；缓存未命中和回退调用可能增加成本，不承诺固定节省比例。 ([#2435](https://github.com/oceanbase/powercontext/pull/2435), [#2776](https://github.com/oceanbase/powercontext/pull/2776), [#2717](https://github.com/oceanbase/powercontext/pull/2717))

- 新增可选的 one_pass Atomic Memory 处理模式，并支持在 Agent 缓存前缀后运行其多步对话。提取、相关记忆协调和复查在同一对话中完成，发布前仍由 Core 校验。前缀路径还会将参与比较的已有记忆发送给 Agent 使用的模型和账户。质量和总成本取决于负载、模型与缓存情况，默认处理模式保持不变。 ([#2729](https://github.com/oceanbase/powercontext/pull/2729), [#2775](https://github.com/oceanbase/powercontext/pull/2775))

- 目录插件可从校验后的快照热重载，激活前运行插件自有的数据升级，并通过 OpenAPI 和 MCP 暴露声明的路由。Server runner 与设备 runner 可按集中管理的目标采集 Source。插件负责自身数据和升级逻辑；备份时需同时保留 Core 存储、插件数据库和本地快照。 ([#2638](https://github.com/oceanbase/powercontext/pull/2638), [#2639](https://github.com/oceanbase/powercontext/pull/2639))

- 扩展各供应商的 OAuth 订阅适配器，新增 Deep Agents 集成。完善 DSH 伴侣记忆、长提示词召回、凭证转发，以及跨集成共享的提示词隐私处理。订阅路由仍受文档列明的协议与保护限制约束，并遵循供应商和账户的用量规则。 ([#2562](https://github.com/oceanbase/powercontext/pull/2562), [#2684](https://github.com/oceanbase/powercontext/pull/2684), [#2656](https://github.com/oceanbase/powercontext/pull/2656), [#2647](https://github.com/oceanbase/powercontext/pull/2647), [#2669](https://github.com/oceanbase/powercontext/pull/2669), [#2712](https://github.com/oceanbase/powercontext/pull/2712))

- 在 Dashboard 中更清晰地查看处理失败和召回决策，包括发布失败、模型用量记账失败和供应商失败。将同次执行的上下文准备诊断独立于 Source 和公开的不含正文的 Receipt 保存；这些私有诊断可能包含查询及候选和最终文本，且不会自动过期。新增 Experience 重复出现效果的只读视图。 ([#2664](https://github.com/oceanbase/powercontext/pull/2664), [#2681](https://github.com/oceanbase/powercontext/pull/2681), [#2676](https://github.com/oceanbase/powercontext/pull/2676), [#2708](https://github.com/oceanbase/powercontext/pull/2708), [#2598](https://github.com/oceanbase/powercontext/pull/2598), [#2688](https://github.com/oceanbase/powercontext/pull/2688))

- 改进长候选对短相关记忆的召回，等待 Source 配置锁，允许在 Experience 孵化期间采集 Source，更可靠地完成待写入的用量记录，并保留 Gateway 中不同的终结回合。 ([#2628](https://github.com/oceanbase/powercontext/pull/2628), [#2691](https://github.com/oceanbase/powercontext/pull/2691), [#2693](https://github.com/oceanbase/powercontext/pull/2693), [#2706](https://github.com/oceanbase/powercontext/pull/2706), [#2717](https://github.com/oceanbase/powercontext/pull/2717))

- Server、Gateway、SDK、CLI 与集成需协调升级。累计迁移冻结为 v1_6_0，接在保留的 v1_5_2_pr2639 之后；1.6.0 的 schema head 为 v1_6_0。该迁移新增私有上下文准备诊断存储，不回填历史查询。已有托管数据库需要显式维护。仍保留旧插件登记或数据的数据库没有受支持的原地升级路径，卸载插件不会删除这些记录。数据库升级支持仅限于通过完整 Server 验收的源版本、目标产物、后端与配置组合。 ([#2713](https://github.com/oceanbase/powercontext/pull/2713), [#2639](https://github.com/oceanbase/powercontext/pull/2639), [#2664](https://github.com/oceanbase/powercontext/pull/2664))

### 安装与兼容性

```bash
uv tool install --force "powercontext[cli,server]==1.6.0"
```

集成安装引用使用 `powercontext-v1.6.0`，升级后重新打开 Agent 会话。Gateway 仍为可选组件，正式发布不会自动开启前缀提取。按知识库指南安装插件和可选依赖。升级门禁保留全部十二种已登记的 1.3.0 来源、后端与配置组合；独立登记的 1.4.0 路径不由该门禁认证。未发布 `000` 创建的数据库和恢复计划可丢弃，应重新构建，不能直接标记为已发布版本。
